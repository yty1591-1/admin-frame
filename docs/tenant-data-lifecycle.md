# 租户数据生命周期（保留期 / 导出窗口 / 硬删除边界）

> 关联：D-05（三段式数据处置）、ADR-0006、ENT-15（配额执行与用量）、`docs/audit/EVENTS.md`（`tenant.data_purge`）
>
> 归口说明：本文只定义**租户侧**的接口、时间线与验收；通用数据处置平台
> （导出执行、跨域级联、报告归档）归 ENT-15。本文与 ENT-15 的分工：
> 租户域提供「哪些数据、什么顺序、什么边界」，ENT-15 提供「怎么删、怎么验」。

## 总原则（D-05：合同与证据闭环）

租户终止（`terminated`）后，数据处置分**三段**执行，每一段都有可验证的证据链：

1. **保留期**：数据原样保留，仅冻结（不可登录、不可读写），支持合同约定的回溯与争议期；
2. **导出窗口**：生成可校验的数据导出包，客户确认签收（或逾期视为放弃）；
3. **硬删除边界**：按边界清单物理删除，写 `tenant.data_purge` 审计并出报告。

三段缺一不可：只保留不导出，客户拿不走自己的数据（合规风险）；
只删除不保留，争议期无据可查（法律风险）；全程无审计，无法向监管证明处置得当。

## 时间线（默认值，可按合同覆盖）

```
terminated ──► 保留期（默认 90d）──► 导出窗口（默认 30d）──► 硬删除（立即执行）
   │                │                      │
   │                │ 冻结：登录 403、        │ 导出包生成 + 校验
   │                │ 守卫拒绝、会话已撤销      │ 客户签收 / 逾期视为放弃
   │                │                      │
   └── tenant.data_purge 审计在硬删除完成时写入 ◄──────┘
```

| 阶段 | 时长 | 配置键（T-23 约定，ENT-15 落地） | 说明 |
|---|---|---|---|
| 保留期 | 90 天 | `tenant.retention.hold_days` | 从 `terminated_at` 起算；合同可约定延长，延长必须留审计 |
| 导出窗口 | 30 天 | `tenant.retention.export_days` | 生成导出包 + 通知客户签收；逾期未签收视为放弃并进入硬删除 |
| 硬删除 | 到期立即 | `tenant.retention.purge_batch_size` | 分批删除（默认 500 行/批），避免长事务；完成后出报告 |

## 各域数据与硬删除边界

租户是隔离边界（ADR-0006），`tenant_id`（即 B 端各表 `merchant_id`）是级联主键。
硬删除按依赖顺序执行，**成员与配额随租户级联（FK ON DELETE CASCADE）先行**，
IAM / identity 的商户数据在租户行删除后按各自域的边界清理：

| 域 | 数据 | 边界 | 级联方式 |
|---|---|---|---|
| 租户 | `tenant` / `tenant_member` / `tenant_quota` / `tenant_invitation` | 全删 | FK 级联（000008/000011/000014） |
| 审计 | `tenant.*` 事件流 | **不删**（180d/365d 归档期独立于租户生命周期，处置本身必须有据可查） | — |
| IAM | 角色 / 绑定中 `merchant_id` 的行 | 删（成员关系消灭后绑定无意义） | ENT-15 级联任务 |
| identity | 商户账号 / 会话 | 删（会话已在停用时撤销） | ENT-15 级联任务 |
| 业务域（订单等） | `merchant_id` 关联数据 | 按各域保留策略（合同约定的更长期限优先） | 各域自治，不在本文范围 |

**审计是唯一不删的**：`tenant.data_purge` 事件本身必须落在删除之后、永久可查，
否则「我们删过了」无法自证。

## 导出包的内容与校验

导出包（ENT-15 执行，租户域验收）必须包含：

1. 租户主数据（含元数据与配额快照）与成员名册；
2. 该租户全部业务数据（按各域清单，ENT-15 汇总）；
3. **清单文件（manifest）**：每个文件的行数与 SHA-256，校验失败即视为导出未完成，
   不得进入硬删除——「导出可校验」是 D-05 的硬性验收项。

## 到期流程与证据链

到期任务（ENT-15 的定时任务）按以下顺序执行，每步留痕：

1. 扫描 `terminated_at + hold_days + export_days < now` 的租户；
2. 确认导出包存在且 manifest 校验通过（无导出 → 跳过并告警，**不得直接删**）；
3. 分批硬删除（按边界表顺序），每批记录行数；
4. 写 `tenant.data_purge` 审计：`attrs.tenant_id` / `attrs.tables` / `attrs.rows_deleted` /
   `attrs.export_manifest_sha256`；
5. 生成处置报告归档（报告本身保留期 ≥ 365d）。

**失败处置**：任一步失败即中止本轮（幂等重试安全——删除按边界清单推进，
重跑只删剩余行）；连续失败升级平台值班，**不允许**为赶进度跳过校验直接删。

## 演练与验收

- **到期流程可演练**：测试环境构造 `terminated_at` 早于边界的租户，验证任务
  全链路（跳过无导出的租户、分批删除、审计写入、报告生成）；
- **导出可校验**：manifest 行数 / 哈希与实际文件一致；
- **硬删有审计与报告**：`tenant.data_purge` 事件存在且字段完整。
