# 密钥泄露应急

| 字段 | 内容 |
|------|------|
| 告警 ID | 无自动告警；由泄露线索（外部通报、仓库扫描、日志异常）触发 |
| 级别 | P1（按安全事故处理） |
| 服务 / 端 | admin-api、biz-api、c-api、worker；数据库、Redis、对象存储 |
| 最后更新 | 2026-11-02 |

## 症状

- 触发条件（满足任一即进入应急）：
  - 签发密钥（JWT `secret` / `keys[].private_key_file`）疑似外泄；
  - 摘要密钥（`identity.hash_key`）或字段加密 KEK 出现在日志、镜像层、公开仓库；
  - 数据库 / Redis / 对象存储凭据出现在提交历史或工单附件；
  - 出现无法解释的令牌签发（例如同一 kid 签发了本系统从未签发给该主体的令牌）。
- 用户可见表现：本身可能**无任何异常**——这正是泄露最危险之处；异常表现可能是
  异地登录、批量会话接管、越权访问审计中出现的陌生操作者。

## 影响

- 影响端与范围：
  - JWT 签发私钥泄露 → 攻击者可伪造**任意主体、任意端**的访问令牌，等同于全系统越权；
  - 摘要密钥泄露 → 可对主体标识做碰撞比对，属 PII 关联风险，不直接导致登录；
  - DB / Redis 凭据泄露 → 直读业务数据与审计表，风险等级等同数据库失陷。
- 数据正确性风险：**有**。泄露窗口内的审计记录需视为可能被污染，取证时要记录「窗口 + 影响表」。

## 排查

1. **确定范围**（15 分钟内完成，先定边界再动手）：
   - 泄露的是哪一类密钥、哪个 kid / key id、哪个环境；
   - 泄露渠道（仓库、镜像、日志、第三方）与首次暴露时间；
   - 该密钥在哪些进程、哪些副本、哪些历史版本中被使用。
2. **确认是否已被利用**：
   - 查 `identity_token_verify_total{result="failure"}` 与 `identity_jwt_issued_total` 的时间序列是否出现与业务无关的突增；
   - 检索审计 `auth.login` / `auth.token.refresh` 的异常主体、来源 IP、`service`；
   - 检索 `iam.breakglass` 与 `rbac.*` 事件是否有未授权变更；
   - 检查数据库连接来源是否出现陌生地址（DB 侧审计 / 慢查询来源）。
3. **固定证据**：导出相关时间窗的审计（用审计查询接口，导出行为本身会再记一条 `data.export`），
   保留原始日志与容器镜像 digest，不做清理性操作。

## 缓解与恢复

**顺序：先止血，再轮换，最后复盘。** 任何「先调查清楚再处理」的做法都不接受。

1. **立即止血（0–30 分钟）**
   - JWT 私钥泄露：把 `auth.jwt.active_kid` 切到新 kid、**从 `keys` 中删除泄露的 kid**，滚动重启全部端。
     该 kid 签发的所有令牌立即失效（预期出现一次全端重新登录）。
   - 摘要密钥泄露：生成新 `hash_key` 与新 `hash_key_id`，旧密钥**不放** `previous_hash_keys`（泄露密钥不允许继续参与读取），
     改为按 §5 的「受限擦除 + 重建索引」流程处理历史主体。
   - DB / Redis 凭据泄露：吊销旧账号 / 改密，先在 DB 侧禁用旧账号再发布新 DSN，避免窗口期双活。
   - 若判断攻击者已在用令牌：对受影响主体执行 `logout-all`，并对管理员触发 [iam.md](./iam.md) 的破玻璃复核。
2. **轮换**：按 [key-rotation.md](./key-rotation.md) 执行完整轮换，唯一区别是
   **不留重叠期**（旧密钥直接移除），并记录由此产生的用户重新登录量。
3. **收口验证**
   - 用泄露密钥尝试访问任一受保护端点，必须返回 401；
   - 审计中不再出现该 kid / 该凭据来源；
   - 所有副本配置一致（逐个 Pod 核对 Secret 版本）。
4. **清理暴露面**
   - 从仓库历史、镜像层、日志系统中移除泄露材料（仓库历史改写需负责人审批）；
   - 轮换 CI/CD、监控、第三方系统中可能复用的同一凭据；
   - 更新 `.gitleaks.toml` 规则，补上本次漏检的形态。

## 升级

- 确认泄露即刻升级：安全负责人 + 架构 Owner + SRE 值班长，**同步启动事故通道**（不等指标异常）。
- 涉及真实用户数据可读：按合规流程评估通报义务，由安全负责人决定对外口径。
- 30 分钟内未能完成止血（新密钥未生效 / 旧密钥仍可用）：升级至 CTO 级别决策，考虑整体下线受影响的认证入口。
- 升级联系：见 [README.md](./README.md) 值班入口。
