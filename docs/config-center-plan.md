## 一、结论摘要

### 1.1 评审结论

**结论：前置条件已满足（v0.4，ADR-0013 / ADR-0014 已评审通过）。** 方向正确——自研、复用现有 MySQL / Redis / Outbox / 审计 / IAM，不引入外部配置平台；范围已从「只接管动态非启动配置」扩大为「**删除 `./configs` 全部运行时静态配置 + 业务密钥托管 + 首次启动自动初始化**」。8 个前置条件已按下表关闭，可进入 M1 编码：

### 1.2 关键决策

| ID | 决策 | 理由摘要 |
|----|------|----------|
| D1 | 自研模块，不引入 Nacos / Apollo / Consul / etcd | 复用既有 MySQL 与治理体系；避免新增 HA、凭据、运维与安全面；与 ADR-0009「能用既有设施满足就不新增组件」一致 |
| D2 | MySQL 为唯一事实源；Redis 只做快照缓存与失效广播（可选） | 事务、版本、审计、PITR 均已具备；Redis 不承担正确性 |
| D3 | M1 不新增可执行文件；`internal/configcenter` 作为模块化单体域，管理面挂 `admin-api`；M2 因密钥解析新增 `cmd/config-api` | 避免过早拆服务；但密钥解密必须收敛到能访问 KEK 的独立工作负载（ADR-0014） |
| D4 | 发布模型为「不可变 release 快照 + 指针 CAS 原子切换」 | 客户端永不看到半发布状态；回滚可追溯；避免逐 key 生效导致配置撕裂 |
| D5 | 客户端采用「进程内缓存 + 版本轮询 + 本地快照」，默认 5s 收敛 | 满足秒级变更；零新增中间件；与 featureflag 的 TTL 模式一致 |
| D6 | **M1 只支持全量发布**（`strategy=all`，发布即切换生效指针）；百分比 / 租户 / 渠道 / 实例灰度降级 P1 | M1 读路径只认 `env + namespace` 的单一生效指针，无目标匹配；若允许策略落库，客户端会全量拿到本该灰度的值，属于静默错配。灰度选择器保留枚举与 `target_rule_json` 字段作为 P1 契约占位，服务端对非 `all` 直接返回 `40000` |
| D7 | **全量接管** `./configs` 下运行时静态配置；不保留引导配置清单与导入清单 | 用户明确要求删除静态配置文件；配置优先级只保留「配置中心 > 代码默认值」；启动装配键仍由中心提供，但只在启动期读取，变更需重启 |
| D8 | 与 featureflag 分治：布尔开关归 featureflag，结构化值与版本发布归配置中心 | 避免两套开关语义互相污染 |
| D9 | 管控端复用 Vben Admin（`frontend/apps/web-admin`） | 复用登录、权限、菜单、请求封装与错误信封；不新建控制台 |
| D10 | 写、发布、审批三权分离：`config:write` / `config:publish` / `config:approve` | 满足企业级职责分离与双人复核；紧急变更走 break-glass 并强制事后审计 |
| D11 | **业务密钥由配置中心托管密文**：每版本独立 DEK，AES-256-GCM 信封加密，KEK 放外部 KMS / Vault / HSM | 用户要求密钥纳入配置中心；明文与根密钥不入库；KEK 与密文分离，降低库泄露影响 |
| D12 | **密钥解析新增 `cmd/config-api` 内部服务**：mTLS / SPIFFE + 服务授权 + 短租约 + 服务端解密 | 业务进程不接触 KEK；避免 `admin-api` 与 B/C 端 HTTP 互调（ARCH §4.4）；密钥访问收敛到单一工作负载 |
| D13 | **签名快照**：Ed25519 签名、客户端内嵌公钥校验，用于冷启动与灾备兜底 | 删除 `configs` 后必须有离线兜底；快照不含密钥明文；签名失败拒绝使用 |
| D14 | **全量迁移与删除 `configs`**：盘点 → 双读对比 → 切换 → 删除文件 → CI 禁止回退 | 避免「删了文件但漏迁配置」；保留 Git 历史，不保留运行时文件 |
| D15 | 密钥权限独立于普通配置：`config:secret:read/write/approve` + 服务身份 `config:secret:resolve` | 普通 `config:read` 不得查看密钥；人不可调用解析接口；服务授权默认拒绝 |
| D16 | **首次初始化（ADR-0017，被 ADR-0018 修订）**：所有环境统一经安装态 + setup token 向导播种（dev 由本地脚本自动驱动向导）；`secret_rule` 密钥按规则生成或占位 | 取消「一律无引导」；需人确认业务基线；dev 一键可启由脚本提供；幂等、不覆盖、强制审计 |
| D17 | **重配置态（repair）与启动降级（ADR-0018）**：阻塞判定只看缺键；缺键时仅 admin-api 降级为 setup-only 并保留向导；`ready` 后允许 `begin(repair)` 且只能改冻结的阻塞键；敏感项默认自动生成、可选覆盖；dev/test 与 prod 共用同一安装路径 | 消除「缺键 → 全进程退出 → 向导打不开」死锁；避免向导沦为日常配置渠道；两套播种逻辑合一，dev 即可验证向导链路 |

### 1.3 与既有能力的边界

| 能力 | 归属 | 说明 |
|------|------|------|
| 首次启动初始化 | 配置中心（ADR-0017 / ADR-0018） | 所有环境统一走安装向导 + setup token；本地脚本自动驱动；真相表 `config_install_state`；幂等且不覆盖；密钥按 `secret_rule` 生成/占位 |
| 配置中心自身连接参数 | 代码默认值 / 部署编排 | 配置中心地址、环境、服务身份、CA、自身 DB / Redis 连接参数不进入业务配置层；口令与 KEK 访问凭据不入配置库 |
| 运行时静态配置 | **配置中心** | `configs/**` 全量迁移（admin / biz / c / worker 与 modules）；启动期读取，变更需重启 |
| 运行时可热更业务参数 | **配置中心** | 限流阈值、分页上限、文案、白名单、通知重试次数等 |
| 业务密钥 | **配置中心（密文托管）** | 第三方 API Key、SMTP / 短信凭据、Webhook 签名密钥、业务加密 / 签名密钥等；服务端解密 + 短租约 |
| 根密钥 / KEK | 外部 KMS / Vault / HSM | 永不入库；配置中心只持有 KEK 引用与访问身份；信封加密的 wrap / unwrap |
| 基础设施口令 | 基础设施 / 部署编排 | 业务进程 DB / Redis 口令、K8s 凭据等不是业务配置项，不入配置中心；按基础设施流程管理 |
| 布尔开关 / 灰度开关 | `internal/featureflag` | 已有 ADR-0009；配置中心不重复实现布尔评估 |
| 审计 | `audit_event` + `internal/platform/audit` | 配置与密钥事件统一发 `config.*` / `config.secret.*`，不建第二套审计表 |
| 异步事件 | `async_outbox` + `pkg/outbox` | 发布 / 回滚 / 密钥轮换事件走 Outbox，消费方可选订阅 |
| 权限 | IAM 权限点与中间件 | 不新建权限体系；新增配置域与密钥域权限点 |
| 管控端 | `frontend/apps/web-admin` | 复用 Vben Admin 5.7 与现有菜单 / 权限指令 |

### 1.4 明确不做（防 scope creep）

- 不做配置中心微服务集群、独立网关或独立注册中心；M2 的 `cmd/config-api` 只做内部密钥解析，不承载管理面与独立网关。
- 不做 Nacos / Apollo 协议兼容或数据迁移。
- 不做配置项级毫秒推送（WebSocket / gRPC stream）。
- **不做配置导入清单文件**：所有环境仅允许安装向导（ADR-0017 / ADR-0018），不做批量导入文件格式。
- **不做根密钥 / KEK 托管**；配置中心自身 DB / Redis 与业务进程基础设施口令不进入配置库（不属于业务配置项）。
- **不做密钥明文托管、明文导出、前端回显、日志打印**；不做业务进程直连 KMS / Vault 解密。
- 不做业务密钥以外的凭据托管（K8s 集群凭据、云账号根密钥、人员口令、SSH 私钥）。
- 不做 ABAC、表达式 targeting、A/B 实验平台。
- 不做自动跨环境同步；跨环境复制必须显式 diff + 审批。
- 不做 K8s Operator / CRD / Sidecar（密钥注入不做 CSI Driver）。
- 不做多语言 SDK（P2 触发后再评估）；密钥解析先只提供 Go SDK 与内部 HTTP。

## 二、现状、约束与评审口径

### 2.1 项目技术基线

| 维度 | 现状 | 对本规划的影响 |

### 2.4 评审口径与优先级

**优先级定义**：

- **P0（MVP 上线阻断）**：缺失则无法安全上线或无法回滚。
- **P1（上线后 90 天）**：企业运营与治理必需，但不阻断首版。
- **P2（规模化 / 合规触发）**：有明确规模或合规诉求再启动，避免过度设计。

**必要性四问**（任一为「否」则降级或剔除）：

1. 是否是生产上线阻断项？
2. 是否已有更简单的替代（文件 / featureflag / Vault / 现有接口）？
3. 不做的直接后果是否可接受？
4. 是否能用既有设施在 MVP 内闭环？

**企业级基线对齐**：变更审批与职责分离、不可变审计轨迹、SLO / 错误预算、容量与压测、RPO / RTO、最小权限、密钥托管、供应链与许可证、演练与复盘。本文只做「对齐」，不声称取得任何认证。

## 三、技术栈选型规划

### 3.1 总体架构

```text
┌──────────────────────────────────────┐
│ Vben Admin（web-admin）               │
│ 配置列表 / 编辑 / 发布 / 回滚          │
│ 密钥列表 / 轮换 / 授权 / 审批（M2）    │
└──────────────────┬───────────────────┘
                   │ HTTPS  /admin/v1/configs/*
                   v
┌──────────────────────────────────────────────────┐
│ admin-api                                        │
│  internal/configcenter                           │
│  transport/admin → app → domain                  │
│  infrastructure/persistence / kms                │
└───┬───────────────┬───────────────┬──────────────┘
    │               │               │
    │               │               ├──► KMS / Vault / HSM（KEK，外部）
    │               │               │      wrap / unwrap DEK；不存业务密文
    │               ├──► async_outbox（config.release.* / config.secret.*）
    │               ├──► audit_event（config.* / config.secret.*）
    │               └──► Redis（可选：快照缓存 / 失效广播）
    v
┌──────────────────────────────────────┐      ┌────────────────────────────────────┐
│ MySQL 8.0（唯一事实源）               │◄─────┤ cmd/config-api（M2 新增）           │
│ config_item / version / release       │ 只读 │ 内部 mTLS / SPIFFE                  │
│ config_release_pointer / signature    │      │ /internal/v1/configs/secrets/resolve │
│ config_secret / secret_version / grant│      │ 服务端解密 + 短租约 + 访问审计       │
└──────┬───────────────────────────────┘      └──────────────▲─────────────────────┘
       │ 只读查询（版本 + 签名快照）                            │ 短租约 / grant
       │                                                       │
┌──────┴───────────────────────────────────────────────────────┴─────┐
│ biz-api / c-api / worker                                             │
│  pkg/configclient（进程内缓存 + 轮询 + 本地签名快照）                  │
│  secret resolver（内存缓存，不落盘；不接触 KEK）                       │
│  bootstrap：代码默认值（首次启动自动初始化，无引导清单）                 │
└──────────────────────────────────────────────────────────────────────┘
```

**关键点**：

- 业务进程**不调用** `admin-api` 读取配置，避免违反 ARCHITECTURE §4.4「A/B/C 进程不得以 HTTP 互调作为内部实现路径」；密钥解析调用独立的 `cmd/config-api`，消费侧定义窄接口，按 §4.4 的「拆分服务 + 同步 RPC + 另立 ADR」路径落地。
- 非密钥配置读路径直连 MySQL（只读账号 + 小连接池），或经可选 Redis 缓存；Redis 不可用时自动回源 MySQL。
- 发布写路径只在 `admin-api`，事务边界清晰；事件与审计同事务写入 Outbox。
- 客户端永远以「本地签名快照」为第一读源，中心故障不影响业务流量；签名快照不含密钥明文。
- 密钥密文只在 MySQL；KEK 只在外部 KMS / Vault / HSM；明文只在 `cmd/config-api` 解密瞬间与调用方内存中存在。
- 首次启动只使用代码默认值：无配置记录时按 key spec 播种基线 Release；不维护引导配置清单，不依赖环境变量配置层。

### 3.2 存储层选型

| 组件 | 选型 | 选型依据 | 兼容性说明 | 主要风险 |
|------|------|----------|------------|----------|
| 事实源 | **MySQL 8.0（现有实例 / 独立 schema）** | 需要事务、唯一约束、版本号、审计关联、PITR 与成熟运维；现有迁移 / 备份 / 监控体系可直接复用 | `database/sql` + `pkg/db`；utf8mb4_0900_ai_ci；DATETIME(3) UTC；JSON 列已在 featureflag 使用 | 连接压力、发布锁竞争、大快照查询；通过索引、短事务、只读连接池、快照上限缓解 |
| 密钥密文 | **MySQL（`config_secret_version`）** | 与配置同库便于事务、审计关联与备份；密文 + nonce + wrapped DEK + KEK `key_id`；库泄露不等于明文泄露 | AES-256-GCM；DEK 每版本独立；AAD 绑定 `env/namespace/key/version`；密文列不参与列表查询 | KEK 不可用时无法解密；DB + KMS 同时失陷才可能还原明文；需 KEK 轮换与备份 |
| KEK | **外部 KMS / Vault Transit / HSM** | 根密钥与数据分离；复用现有 `internal/platform/secrets` Vault Provider；支持轮换、审计与访问控制 | 只提供 wrap / unwrap；不存业务密文；`key_id` 入配置库用于轮换映射 | KMS 故障导致密钥解析不可用；需降级与告警；跨云 / 自建方案需选型 |
| 读缓存 / 失效广播 | **Redis 7（可选）** | 降低多实例版本轮询与快照回源的 DB 压力；`pkg/redis` 已具备 | `redis.addr` 已存在；生产强制 Redis；dev 可退化为直连 MySQL | 缓存与事实源不一致；只做加速，不做正确性依赖，失效即回源 |
| 本地签名快照 | **进程本地文件（原子写 + Ed25519 签名）** | 中心 / DB 故障时继续服务；删除 `configs` 后的冷启动与灾备兜底；零新增组件 | 容器内 `emptyDir` 或挂载卷；文件含 `release_id`、hash、签名、`key_id`；**不含密钥明文** | 容器重建丢失；签名私钥泄露可伪造；公钥内嵌二进制；无快照 + 无中心时按 `required` 分级 |
| 导出 / 归档 | **对象存储（现有 S3 兼容驱动，P1）** | 配置导出、变更归档、灾备副本；复用 `pkg/storage` 与现有桶 | 仅管理面使用，不在读路径；**密钥只导出元数据，不导出密文 / 明文** | 生命周期与权限配置错误；复用现有 bucket 策略与审计 |
| 不选 | etcd / Consul / ZooKeeper / Nacos / Apollo | 需要强一致 KV 或外部平台；会新增 HA、凭据、升级、安全与运维面 | — | 与「不重复建设」「不新增组件」冲突 |

**存储结论**：MySQL 承担正确性、版本事实与密钥密文；KEK 外部托管；Redis 只做可选加速；本地签名快照承担降级；对象存储只做配置导出归档。**不引入新的有状态组件。**

### 3.3 服务层选型

| 项 | 选型 | 依据 |
|----|------|------|
| 形态 | 模块化单体新域 `internal/configcenter`，含 `domain/config` 与 `domain/secret` 两个子域 | 与 `identity` / `iam` / `tenant` / `notification` / `featureflag` 一致；共享 `platform.Run` 与 IAM |
| 分层 | `domain` / `app` / `infrastructure` / `transport/admin` / `transport/internal` | 符合 ARCHITECTURE 分层与依赖方向；domain 零框架依赖 |
| 管理面宿主 | `cmd/admin-api` | 仅 A 端平台治理；B/C 端不暴露配置或密钥管理 |
| 密钥解析服务 | **M2 新增 `cmd/config-api`**：只承载内部 `/internal/v1/configs/secrets/*` 与健康检查；mTLS / SPIFFE；不承载管理面 | 解密收敛到单一工作负载；`admin-api` 只在创建 / 轮换时执行 wrap；两者均不向业务进程暴露 KEK；避免 admin-api 与 B/C 端 HTTP 互调（ARCH §4.4） |
| 普通配置读 | 业务进程直连 MySQL 只读；M2 后可选经 `config-api` 统一 | 读路径无新增单点；`config-api` 故障不影响非密钥配置 |
| 事务 | app 层单事务；发布 = 元数据 + 指针 CAS + Outbox + 审计；密钥轮换 = 版本 + 状态 + 审计 | 禁止长事务与跨远程事务；快照构建在事务外完成；KMS wrap 在事务外完成 |
| ID | 雪花 ID（`platform.Deps.IDs`） | 与 IAM / tenant 表一致；禁止自增 |
| 后台任务 | `cmd/worker` 承担到期归档、审批超时提醒、DEK 重包裹、缓存预热（P1） | 复用 worker 生命周期；不新增 cron 进程 |

**`cmd/config-api` 拆分理由**（与 v0.1「MVP 不新增可执行文件」的差异）：

1. 密钥明文只能在「能访问 KEK 的工作负载」内出现；把解密放进每个业务进程等于把 KEK 访问面放大到全部实例。
2. 业务进程需要密钥解析，但不能调用 `admin-api`（ARCH §4.4）；独立 `config-api` 是符合「拆分服务 + 消费侧接口 + ADR」的路径。
3. `config-api` 可独立限流、独立 NetworkPolicy、独立 mTLS 身份与独立审计，故障域小于把密钥端点塞进 admin-api。
4. 非密钥配置仍走「进程内缓存 + 直连 MySQL」，`config-api` 故障不影响普通配置读取。

**后续拆分触发条件**（满足任意 2 条再评估把普通配置读也收敛到 `config-api`）：

1. 配置管理 QPS 或发布频率独立于 admin-api 显著增长，影响 A 端其他接口；
2. 需要独立发布节奏或多区域部署；
3. 客户端规模 > 500 实例且直连 DB 的连接 / 查询压力不可接受；
4. 需要向非 Go 语言或外部系统提供稳定读 API；
5. 配置域团队独立，边界稳定。

### 3.4 接入层选型

| 通道 | 选型 | 说明 |
|------|------|------|
| 管理面（配置 / 密钥） | REST + OpenAPI 3（`api/openapi/admin.yaml`） | 统一信封、分页、错误码；密钥列表 / 详情只返回指纹与版本；`make openapi` 做 breaking 检查 |
| 网关 / 入口 | 复用现有 `admin-api` Ingress、TLS 与 NetworkPolicy | 不新增管理面域名、证书或 WAF 规则；仅新增路由 |
| 内部密钥解析 | **`cmd/config-api` + mTLS / SPIFFE + NetworkPolicy** | 仅集群内可达；服务身份由证书 SAN / SPIFFE ID 确定；默认拒绝；不做公网入口 |
| Go SDK | `pkg/configclient`（配置缓存 / 监听 / 类型化读取）+ `pkg/secretclient`（解析 / 租约 / 内存缓存） | SDK 零业务语义；业务域定义窄接口，`cmd` 注入适配器 |
| 读取协议（配置） | **版本轮询 + 快照拉取 + 本地签名快照** | 默认 5s（可配 1s～60s），抖动 ±20%；变更时按 release_id 拉取快照 |
| 读取协议（密钥） | **短租约 + 单 key / 有限批量解析** | 默认租约 5m（上限 15m），到期前 80% 刷新；单次 ≤ 20 key；不提供「拉全量」 |
| 变更通知 | Redis Pub/Sub（P1，可选） | 只做「提前唤醒轮询」，不做正确性依赖；丢失不影响收敛 |
| gRPC / 长轮询 / WebSocket | MVP 不做 | 增加连接管理与网关改造；5s 轮询已满足业务时效 |
| 多语言 SDK | P2 | 当前后端全 Go；外部系统优先走导出 / 只读 API；密钥解析仅 Go SDK |

**SDK 读取语义**：

```text
配置 Get(key) → 本地 atomic snapshot → 命中即返回（P99 < 1ms）
              → 未命中 → 代码默认值（并打点 config_client_default_total）
              → 类型 / 校验失败 → 默认值 + 告警（不 panic）

密钥 Resolve(name) → 内存租约缓存命中 → 返回（不落盘、不打印）
                   → 未命中 → 调 config-api（mTLS）→ 校验授权 → 解密 → 租约缓存
                   → 失败 → required=true 则返回错误 / 启动失败；否则调用方降级
```

**密钥解析约束**：

- 只允许服务身份调用，人不可调用；不提供 `curl` 式调试通道（排障走离线审批 + 受控工具）。
- 返回体不包含 KEK、wrapped DEK、密文或 `key_id` 以外的内部字段；日志只记录 key 名、版本、结果。
- 租约只缓存在内存；进程退出即失效；不支持跨进程共享缓存。
- 吊销 / 轮换后旧租约最长存活一个 TTL；高风险密钥可配置 `lease_ttl=60s` 或强制 `no-cache`。

**SDK 版本兼容**：服务端至少兼容 N-2 个 SDK 次版本；只做加法字段；删除 / 改语义须升 major 并保留一个发布周期。

### 3.6 选型对比与落选理由

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Nacos / Apollo | 成熟、带控制台、支持灰度与监听 | 新增外部平台、HA、数据库、升级、凭据、安全与运维面；与 ADR-0009 取向冲突 | 不选 |
| Consul / etcd | 强一致 KV、Watch 成熟 | 无版本 / 审批 / 审计 / 灰度模型；运维与容量成本高；仍需自建管控面 | 不选 |
| Redis 作为事实源 | 快、简单 | 持久化与事务弱；无版本、审批、审计；故障可能丢配置 | 仅作缓存 |
| 纯文件 / ConfigMap | 零组件、GitOps 友好 | 无热更、无灰度、无审计、无权限；变更需发布；用户已要求删除 | 不选（首次启动用代码默认值） |
| 独立 config-api 服务 | 边界清晰、可独立扩缩 | 新增工作负载、服务发现、鉴权、网络策略与发布编排 | **M2 仅用于密钥解析**；普通配置读不拆 |
| **自研模块 + MySQL + 本地签名快照** | 复用现有设施；事务 / 审计 / 权限 / 观测齐全；运维面最小 | 需要自建发布 / 灰度 / 客户端模型 | **选中** |
| Vault 作为密钥存储（配置中心只存引用） | 成熟、动态凭据、审计完善 | 新增外部平台与 HA 依赖；用户要求配置中心接管密钥；控制台 / 审批与本项目 IAM 割裂 | 不选；**只把 Vault 当 KEK** |
| 云厂商 Secrets Manager | 托管、免运维、与 KMS 集成 | 厂商锁定、跨云不一致、成本与合规边界；无法复用本项目审计 / 审批 | 不选 |
| K8s Secret 作为业务密钥存储 | 原生、注入简单 | 无版本 / 审批 / 轮换 / 细粒度授权 / 访问审计；etcd  encrypted 不等于业务级托管 | 只用于基础设施口令，不用于业务密钥 |
| **自研信封加密（DEK + 外部 KEK）** | 密文与根密钥分离；复用 MySQL / IAM / 审计；支持轮换与租约 | 需自建密钥生命周期、KMS 适配与密钥演练 | **选中（ADR-0014）** |

### 3.7 供应链与新技术依赖

- MVP **零新增直接依赖**：HTTP、JSON、哈希、AES-GCM、Ed25519、文件原子写均用标准库；数据库 / Redis / 审计 / Outbox 复用现有包。
- KEK 访问优先复用现有 `internal/platform/secrets` 的 Vault `Provider`；若目标环境使用云 KMS 或 HSM，新增 SDK 须走 DEP / LIC 评审，优先官方 SDK + Apache-2.0 / MIT。
- 若 P2 引入 JSON Schema 校验库，须走 DEP / LIC 评审，且不得进入读路径。
- 不新增 sidecar、agent、Operator、独立数据库或消息队列；M2 新增 `cmd/config-api` 工作负载（Deployment + Service + NetworkPolicy + mTLS 证书）。
- 管理面镜像不变；M2 新增 `config-api` 镜像（可与主镜像同仓库、不同 entrypoint）；新增迁移、前端页面与证书挂载。

### 3.8 技术选型结论

选择「**模块化单体内的配置中心域 + MySQL 事实源 + 进程内 SDK + 本地签名快照 + 可选 Redis 加速 + M2 独立 `cmd/config-api` 密钥解析 + 外部 KEK 信封加密**」。该方案在可用性、性能、可扩展、易运维四个维度均优于引入外部平台：普通配置读路径无新增网络单点，密钥解析收敛到单一受控工作负载，写路径复用现有事务与审计，根密钥不进入配置库，且与项目现有分层、配置、审计、权限与发布规范一致。

## 四、功能需求梳理与评审

### 4.1 配置全生命周期模型

**配置项（Item）** 是「一个 key 的草稿与版本」；**发布单（Release）** 是「一组配置项版本的不可变快照」。客户端只感知 Release，不感知单个 Item 的中间状态。

```text
Item:     draft ──► active（已有发布版本）──► deprecated ──► archived
            │
            └── 每次保存生成不可变 ItemVersion（1..N）

Release:  draft ──► pending_review ──► approved ──► active
                        │                 │           │
                        │                 │           ├──► superseded（新 Release 生效）
                        │                 │           └──► rolled_back（回滚）
                        │                 └──► cancelled
                        └──► rejected
```

规则：

- Item 不物理删除；删除 = `archived`，历史版本永久保留。
- Release 一旦 `pending_review` 不可修改；只能撤回后新建。
- 回滚 = 以历史 Release 快照为基准创建**新 Release**，不修改历史记录。
- 同一 `env + namespace` 同时只有一个 `active` Release；指针 CAS 保证原子切换。

| CC-F-52 | 密钥双人审批与脱敏 | 单人可创建 / 轮换 / 删除生产密钥 | P0（M2） | 保留 | 创建 / 轮换 / 吊销 / 授权均双人；提交人 ≠ 审批人；明文一次性输入、永不回显 |
| CC-F-53 | 密钥审计与访问审计 | 无法回答「谁在什么时候用了哪个密钥」 | P0（M2） | 保留 | `config.secret.*` 事件 + 解析访问事件；含服务身份、key、版本、结果、trace_id；保留 ≥180 天 |
| CC-F-54 | 禁止明文导出 / 日志 / 快照 | 密钥从旁路泄露 | P0（M2） | 保留 | 导出只含元数据；日志 / 快照 / 指标 / 错误体 / 前端响应均无明文；gitleaks + 单测断言 |
| CC-F-55 | 密钥灾备与恢复演练 | KEK 故障或误删后无法恢复 | P1（M3） | 保留 | 密文与 KEK 分离备份；KEK 轮换 / 恢复演练；RPO / RTO 达标；演练记录归档 |
| CC-F-56 | 密钥字段规则与首次自动生成 | 空环境无法启动；随机生成无约束导致弱密钥或格式不兼容 | P0（M2） | 保留 | key spec 声明 `secret_rule`（长度 / 编码 / 算法 / 是否可自动生成）；仅对声明规则的字段用 `crypto/rand` 生成；生成一次、加密入库、审计；无规则字段必须人工录入，`required` 缺失 fail-fast |

### 4.4 冗余需求剔除清单

| 需求 | 剔除理由 | 替代方案 |

## 五、非功能需求

### 5.1 可用性与 SLO

| 指标 | 目标 | 测量点 | 说明 |
|------|------|--------|------|
| **配置读路径可用性 SLA** | **≥ 99.95% / 月** | 客户端 `Get` 成功返回（签名快照 / 代码默认值均算成功） | 99.95% 对应每月约 **21.6 分钟**不可用预算 |
| **密钥解析可用性 SLA** | **≥ 99.95% / 月** | `Resolve` 成功返回（租约缓存命中或 `config-api` 成功解密） | 与配置读独立统计；`required` 密钥失败会阻断业务启动 / 关键路径 |
| 管理面写可用性 SLO | ≥ 99.9% / 月 | 发布 / 回滚 / 审批 / 密钥轮换接口成功率 | 写路径故障不影响业务读；约 43.2 分钟预算 |
| 发布生效时效 SLO | 99% ≤ 10s；99.9% ≤ 30s | 发布成功到客户端快照版本切换 | 取决于 5s 轮询 + 抖动 + 拉取；非可用性指标 |
| 密钥轮换生效时效 | 99% ≤ 租约 TTL；P99 ≤ 2 × TTL | 轮换成功到所有租约刷新 | 默认租约 5m；高风险密钥可降至 60s |
| 配置持久性 | 已提交配置 / 密钥密文 RPO = 0 | MySQL 事务提交 + binlog / 备份 | 依赖 MySQL HA 与 PITR；KEK 另做备份 |
| 审计完整性 | 关键变更 100% 可追溯 | `audit_event` 与发布 / 轮换记录对账 | 审计写失败时操作失败关闭 |

**错误预算策略**：

- 读路径月度预算消耗 ≥ 50%：冻结非必要配置变更，仅允许 break-glass。
- 预算耗尽：暂停所有配置发布，完成复盘与整改后再恢复。
- 管理面预算不影响读路径，但连续失败需降级为只读并告警。

### 5.2 性能指标与容量模型

| 指标 | 目标 | 说明 |
|------|------|------|
| 进程内 `Get` | **P99 < 1ms，P999 < 5ms** | 原子指针 + 预解码；无锁、无 I/O |
| 快照拉取（DB / API） | **P99 < 50ms，P999 < 200ms** | 单行主键 / 唯一索引查询；快照 ≤ 1MB |
| 管理面列表 | P99 < 200ms | 分页 + 索引；禁止全表扫描 |
| 发布 / 回滚 | P99 < 500ms | 快照构建在事务外；事务只写元数据 + 指针 + Outbox + 审计 |
| 版本轮询 | 默认 5s，可配 1s～60s | 抖动 ±20%；单次查询走 `config_release_pointer` 主键 |
| 单环境容量 | 10k item / 50 namespace / 1MB 快照 / namespace | 超限拒绝发布；大配置拆分 namespace |
| 客户端规模 | 200 实例（MVP 验证），500 实例（P1 目标） | 200 实例 × 1 次 / 5s ≈ **40 QPS** 版本查询 |
| 发布峰值 | 10 次 / 秒（管理面） | 实际远低于此；仍按此做压测上限 |
| 连接池（配置） | 配置客户端每实例 ≤ 2 个只读连接 | 200 实例 ≈ 400 连接；与业务池隔离，避免挤占 |
| 密钥解析（稳态） | **P99 < 50ms，P999 < 150ms** | 租约缓存命中；`config-api` 内存 DEK 缓存；不每次调用 KMS |
| 密钥解析（冷启动 / 缓存未命中） | P99 < 300ms，P999 < 800ms | 含 KMS unwrap；按 key 做 singleflight，避免同一密钥惊群 |
| 密钥解析 QPS | 200 实例 × 20 key / 5m ≈ **13 QPS** | 租约摊平；上限按 100 QPS 压测；单次 ≤ 20 key |
| KMS 调用 | 轮换 / 冷启动 / 缓存失效时调用；稳态接近 0 | DEK 在 `config-api` 内存缓存；KEK 轮换时后台重包裹 |
| 密钥容量 | 5k secret / 环境；单密钥 ≤ 64KB | 密文列不参与列表；超限拒绝创建 |

**容量公式**：

```text
版本查询 QPS ≈ 实例数 / 轮询间隔（秒）
快照拉取 QPS ≈ 发布次数 × 实例数（仅变更瞬间，受抖动摊平）
DB 连接上限 ≈ 实例数 × config_center.client.max_open_conns
建议：max_open_conns=2，实例数 ≤ 500 时 ≤ 1000 连接；超过则启用 Redis 缓存或拆分读副本

密钥解析 QPS ≈ 实例数 × 每实例密钥数 / 租约 TTL（秒）
KMS QPS ≈ 密钥解析 QPS × (1 - DEK 缓存命中率)
建议：租约 5m、DEK 缓存命中率 > 99%；KMS 按 10 QPS 预留，轮换窗口单独评估
```

**压测场景**（登记 `docs/perf/LOAD_BASELINES.md`）：

1. 200 实例 × 5s 轮询 × 10k item × 1MB 快照，持续 30 分钟；
2. 10 次 / 秒发布 + 200 实例同时拉取，验证惊群抑制；
3. MySQL 主库故障切换期间读路径不中断；
4. 快照 1MB 解析耗时与内存占用；
5. 200 实例 × 20 key / 5m 租约解析，验证 `config-api` 与 KMS 调用量；
6. 密钥轮换 + 200 实例租约刷新，验证双版本 grace 与旧实例不中断；
7. KMS 停止 / 延迟注入，验证 `config-api` 降级与告警。

### 5.3 数据一致性与发布原子性

| 场景 | 一致性要求 | 实现 |
|------|------------|------|
| 管理面读 | 读己之写（read-your-writes） | 管理面读写均走主库；MVP 不引入只读副本延迟 |
| 发布 | 原子：要么整体生效，要么完全不生效 | 单事务写 Release / ReleaseItem / 指针 CAS / Outbox / 审计；客户端按不可变快照读取 |
| 客户端读 | 最终一致，收敛 ≤ 10s（P99 ≤ 30s） | 版本轮询 + 快照拉取；本地快照兜底 |
| 灰度 | 同一目标稳定命中同一 Release | 稳定哈希（release_id + salt + target_id），不随请求变化 |
| 审计 / 事件 | 与发布同事务，不丢 | 同事务写 `async_outbox` 与审计；失败则发布失败 |
| 跨 namespace | 不保证原子 | 一个 Release 只属于一个 namespace；跨域变更拆多个 Release，明确不承诺全局原子 |
| 回滚 | 逻辑回滚，不物理回滚历史 | 以历史快照创建新 Release；历史版本不可变 |
| 密钥版本 | 单密钥版本原子切换；轮换期间双版本可解析 | `config_secret_pointer` 或 `active_version` CAS；旧版本保留 grace；不进入配置 Release 快照 |
| 密钥与配置 | 不保证联动原子 | 密钥版本独立于配置 Release；需要联动时由发布编排显式排序，并在 runbook 说明 |

**禁止**：

- 逐 key 生效（会出现配置撕裂）；
- 先改指针后写 Release（会出现指向不存在的快照）；
- 在事务内构建大快照 / 做远程调用；
- 用 Redis 作为唯一事实源；
- **把密钥值写入 Release 快照或签名快照**；
- **在配置 Release 中引用密钥明文 / 密文，只允许引用 secret 名与版本**。

### 5.4 容灾与降级

**故障矩阵**：

| 故障 | 读路径 | 写路径 | 降级 / 恢复 | 告警 |
|------|--------|--------|-------------|------|
| MySQL 主库不可用 | 客户端继续用本地快照；`Get` 不受影响 | 发布 / 回滚失败，返回 503 / `50000` | 等待 HA 切换；读路径无 RTO；写 RTO ≤ 15m | `ConfigDBUnavailable` |
| Redis 不可用 | 回源 MySQL；无影响 | 无影响（缓存非必需） | 自动 bypass；恢复后回填 | `ConfigCacheError` |
| admin-api 不可用 | 无影响 | 管理面不可用 | 业务读不受影响；恢复后继续 | `API5xxRateHigh`（既有） |
| 快照损坏 / 验签失败 | 保留内存中上一份有效快照；尝试重新拉取 | 无影响 | 拉取失败则继续用内存快照；冷启动无有效快照才失败 | `ConfigSnapshotCorrupt` |
| 冷启动 + DB 不可用 + 无本地签名快照 | `required=true` 键缺失 → 拒绝启动；否则默认值 | — | 关键服务 fail-fast；非关键服务降级启动 | `ConfigColdStartDegraded` |
| `cmd/config-api` 不可用 | 租约未过期的密钥继续可用；过期后无法刷新 | 密钥创建 / 轮换 / 吊销不可用；普通配置发布不受影响 | 恢复后租约自动续期；`required` 密钥刷新失败 → 业务失败关闭 | `ConfigSecretAPIUnavailable` |
| KMS / Vault 不可用 | `config-api` 内存 DEK 缓存可继续解密；缓存未命中失败 | 密钥创建 / 轮换 / 重包裹失败 | 恢复后自动重试；禁止回退明文或本地根密钥 | `ConfigKMSUnavailable` |
| 密钥轮换失败 | 旧版本继续可解析，业务无感 | 轮换任务失败并可重试 | 保留旧 `active_version`；修复后重新轮换；审计 | `ConfigSecretRotateFailure` |
| 密钥已泄露 | 吊销后旧租约 ≤ TTL 失效 | 紧急轮换 / 吊销 | 走安全事件流程；强制 `no-cache`；审计与通知 | `ConfigSecretRevoked` |
| 发布事务失败 | 旧指针不变，客户端无感 | 返回失败，可重试 | 事务回滚；幂等重试 | `ConfigPublishFailure` |
| 错误配置已发布 | 客户端已生效 | — | 一键回滚到上一 Release；目标 ≤ 30s | `ConfigRollback` |
| 区域 / AZ 故障 | 随 MySQL HA / K8s 调度 | 同左 | MVP 单区域多 AZ；多区域 P2 | 随基础设施告警 |

**RPO / RTO**：

| 对象 | RPO | RTO | 说明 |
|------|-----|-----|------|
| 已提交配置 | 0 | ≤ 15m（写路径） | MySQL 事务 + binlog / PITR；读路径 0 |
| 密钥密文 | 0 | ≤ 15m（写路径） | 与配置同库；备份加密；不含明文 |
| KEK | 0 | ≤ 30m | 外部 KMS / Vault 的密钥备份与多副本；轮换保留旧 `key_id` |
| 客户端本地签名快照 | 最后一次成功拉取 | 0 | 进程内继续服务；重建后回源 |
| 审计事件 | 0 | 随 MySQL | 同事务 Outbox |
| 配置导出归档 | ≤ 24h（P1） | ≤ 1h | 对象存储版本化；密钥只导出元数据 |

### 5.5 安全与合规

| 要求 | 落点 |
|------|------|
| 最小权限 / 默认拒绝 | 仅 A 端管理端点；`config:read/write/publish/approve` 与 `config:secret:read/write/approve` 分离；B/C 端无管理路由 |
| 职责分离 | 配置提交人 ≠ 审批人；密钥创建 / 轮换 / 吊销 / 授权均双人；生产强制；break-glass 事后补审 |
| 密钥明文 | **不落库、不落快照、不落日志、不落指标、不回显前端、不提供导出**；只在 `config-api` 解密瞬间与调用方内存存在 |
| 密钥密文 | AES-256-GCM 信封加密；每版本独立 DEK；KEK 外部 KMS / Vault / HSM；AAD 绑定 `env/namespace/key/version`；密文列不参与列表查询 |
| 根密钥 | 永不进入配置库、镜像、Git、配置快照；KEK 轮换保留旧 `key_id` 以便解密历史版本 |
| 服务身份 | `config-api` 使用 mTLS / SPIFFE；服务授权按 `env + namespace + service_identity + secret`；默认拒绝；人不可调用解析端点 |
| 传输安全 | 管理面 HTTPS；`config-api` 仅集群内 mTLS；DB / Redis 按现有网络策略与 TLS 配置 |
| 静态加密 | 配置值按数据分级限制；密钥密文独立加密；MySQL 磁盘 / TDE 与备份加密作为纵深防御，不作为唯一控制 |
| 租户隔离 | SQL 强制 `env + namespace`；tenant 覆盖带 `tenant_id`；A 端跨租户需 `all` 范围并审计 |
| 输入 / 输出 | 参数化 SQL；key / value 长度与类型校验；密钥单次 ≤ 20 key；错误不泄露内部堆栈、密文、DEK、KEK |
| 审计 | 配置变更、审批、发布、回滚、导出、密钥创建 / 轮换 / 吊销 / 授权 / 解析全覆盖；保留 ≥180 天；追加写；审计载荷只含 key 名、版本、指纹、结果 |
| 供应链 | 零新增直接依赖；gitleaks / gosec / govulncheck；镜像扫描沿用；KMS SDK 走 DEP / LIC |
| 威胁建模 | STRIDE：仿冒（IAM + mTLS / SPIFFE）、篡改（版本 + 签名 + 审计 + 审批）、抵赖（审计）、信息泄露（信封加密 + 脱敏 + 禁止导出）、拒绝服务（限流 / 快照上限 / 租约）、提权（权限分离 + 服务授权） |

**PII / 数据分级**（对齐 `docs/data-inventory.md`）：配置中心默认只允许 **P0 非敏感** 与 **P3 业务敏感**（需 owner + 审批）；**P1 直接标识 / P2 准标识禁止入库**。密钥 / 凭据只允许进入密钥子域，按 ADR-0014 信封加密；**明文与根密钥永不入库**。该规则写入 `docs/data-inventory.md`、发布校验与密钥创建校验。

**密钥管理专项要求**：

| 要求 | 落点 |
|------|------|
| 密钥分类 | 只托管业务密钥（第三方 API Key、SMTP / 短信、Webhook 签名、业务加密 / 签名密钥）；基础设施口令不入配置中心 |
| 密钥来源 | 创建时一次性输入；不接受从日志 / 工单 / 聊天记录导入；导入只允许加密文件 + 审批（P1） |
| 密钥生成 | 仅对 key spec 声明了 `secret_rule` 的字段自动生成：长度 / 编码（base64url / hex）/ 算法 / 前缀显式约束；使用 `crypto/rand`；首次生成即版本 1 并审计；无规则字段必须人工录入，`required` 缺失 fail-fast |
| 密钥展示 | 列表 / 详情只显示名称、版本、指纹（SHA-256 前 8 位）、owner、到期时间；明文永不回显 |
| 密钥轮换 | 计划轮换 + 手动轮换 + 紧急轮换；默认 90 天提醒；高风险 30 天；旧版本保留 grace（默认 24h，可配 ≤ 7d）；`dual_version=1` 时解析同时返回 active + grace（验签类密钥） |
| 密钥吊销 | 立即标记 revoked；租约 ≤ TTL 失效；支持按服务 / 按版本吊销；吊销不可逆 |
| 密钥授权 | 服务身份 + env + namespace + secret 四元组；新增 / 收回均审计；禁止通配符 `*` |
| KEK 权限 | `admin-api` 仅 wrap、`config-api` 仅 unwrap / 重包裹；分别绑定 ServiceAccount；KMS 审计开启；禁止业务进程持有 KMS 凭据 |
| 密钥备份 | 密文随 MySQL 备份；KEK 由 KMS / Vault 备份；两者分离存放；恢复演练至少一次 |
| 密钥事件 | 泄露、误删、轮换失败、KMS 故障均登记安全事件；按 `docs/incident/` 流程复盘 |

### 5.7 兼容性与演进

| 场景 | 策略 |
|------|------|
| 旧 SDK ↔ 新服务端 | 服务端兼容 N-2 次版本；只加字段；新增能力通过 capability 字段协商 |
| 新 SDK ↔ 旧服务端 | SDK 对未知字段忽略；缺失能力回退轮询 |
| 配置 key 演进 | 新增 key；旧 key 标 `deprecated` + 到期；禁止原地改类型 |
| 配置优先级演进 | 固定为「配置中心 > 代码默认值」；迁移期双读仅用于对比，不作为运行时优先级；M3 删除文件层与环境变量覆盖层 |
| 静态配置加载 | `pkg/config.Loader` 改为：代码默认值 + 配置中心快照 → normalize → Validate；首次启动无记录时按默认值播种，不读取文件 / 环境变量配置层 |
| 无中心 / 无快照启动 | 代码默认值兜底；`required` 键缺失 fail-fast；非关键键用默认值并标记 degraded |
| 密钥版本演进 | 新版本默认 `active`；旧版本保留 grace；`key_id` 不在返回体中暴露给业务；只允许加法字段 |
| 回滚兼容 | 新 Release 可回滚到任意历史 Release；旧客户端只认自己声明的 key，未知 key 忽略；密钥回滚只能通过重新激活旧版本（受审计） |
| 前端兼容 | 新页面独立路由；不改现有菜单与权限；按权限点显隐 |

## 六、架构与数据设计要点

### 6.1 模块与依赖

```text
internal/configcenter/
├── domain/
│   ├── config/             # Item / Release / 状态机 / 校验 / 快照 / 仓储接口
│   └── secret/             # Secret / SecretVersion / 状态机 / 授权 / 租约 / 领域错误
├── app/                    # 用例：配置创建 / 提交 / 审批 / 发布 / 回滚；密钥创建 / 轮换 / 吊销 / 授权
├── infrastructure/
│   ├── persistence/        # MySQL 仓储（Item / Release / Pointer / Secret / Grant）
│   ├── client/             # pkg/configclient 的 MySQL SnapshotSource
│   ├── kms/                # KEK Provider 适配（Vault Transit / 云 KMS / HSM）
│   └── crypto/             # AES-256-GCM 信封加密、Ed25519 签名 / 验签
├── transport/
│   ├── admin/              # Handler / DTO / Router（仅 admin）
│   └── internal/           # /internal/v1/configs/secrets/resolve（仅 config-api）
└── observability/          # 指标注册
pkg/configclient/           # 配置缓存、轮询、签名快照、类型化读取、Watch
pkg/secretclient/           # 密钥解析、租约缓存、刷新、错误分类
cmd/config-api/             # M2 内部密钥解析服务（mTLS / SPIFFE）
```

依赖规则：

- `transport/admin → app → domain`；`transport/internal → app → domain`；`infrastructure → domain`。
- `pkg/configclient` / `pkg/secretclient` 不 import `internal/*`；`internal/configcenter/infrastructure/*` 可 import `pkg/*` 与 `pkg/db`。
- 业务域只定义窄接口（如 `type LimitsReader interface { MaxPageSize() int }`、`type SecretResolver interface { Resolve(ctx, name) (string, error) }`），`cmd` 注入适配器；业务域不 import `internal/configcenter`。
- 管理面不 import 其他业务域实现；权限走 `internal/iam` + `shared/auth` 接口。
- `cmd/config-api` 只装配 `transport/internal` + `app` + `infrastructure`；不注册 admin 路由；不复用 admin-api 的 JWT 会话。

### 6.2 数据模型

> 主键统一雪花 ID；时间统一 `DATETIME(3)` UTC；表 `InnoDB` + `utf8mb4_0900_ai_ci`；禁止物理删除。

| 表 | 关键列 | 约束 / 索引 | 说明 |
|----|--------|-------------|------|
| `config_item` | `id`, `env`, `namespace`, `key`, `value_type`, `description`, `owner`, `status`, `current_version`, `version`, `sensitive`, `validation_json`, `expires_at`, `created_by`, `updated_by`, `created_at`, `updated_at` | `UNIQUE(env, namespace, key)`；`KEY(env, namespace, status)` | 配置项主表；`version` 乐观锁；`sensitive=1` 的值必须走 `config_secret` 子域 |
| `config_item_version` | `id`, `item_id`, `version`, `value_text`, `value_hash`, `change_summary`, `created_by`, `created_at` | `UNIQUE(item_id, version)` | 不可变版本；发布快照引用此表 |
| `config_release` | `id`, `env`, `namespace`, `release_no`, `name`, `description`, `status`, `strategy`, `target_rule_json`, `snapshot_hash`, `snapshot_size`, `snapshot_signature`, `snapshot_key_id`, `based_on_release_id`, `created_by`, `submitted_by`, `approved_by`, `approved_at`, `published_at`, `created_at`, `updated_at` | `UNIQUE(env, namespace, release_no)`；`KEY(env, namespace, status)` | 发布单；`release_no` 单调递增；`snapshot_signature` 为 Ed25519 签名，客户端内嵌公钥验签 |
| `config_release_item` | `release_id`, `item_id`, `item_version`, `config_key`, `value_hash` | `PRIMARY KEY(release_id, item_id)` | 快照成员；发布后不可变；**不含密钥值** |
| `config_release_pointer` | `env`, `namespace`, `active_release_id`, `version`, `updated_at` | `PRIMARY KEY(env, namespace)` | 单行指针；`version` 做 CAS |
| `config_release_review` | `id`, `release_id`, `reviewer`, `decision`, `comment`, `created_at` | `KEY(release_id)` | 审批记录；提交人 ≠ 审批人 |
| `config_secret` | `id`, `env`, `namespace`, `name`, `description`, `owner`, `status`, `active_version`, `version`, `rotate_interval_days`, `dual_version`, `expires_at`, `created_by`, `updated_by`, `created_at`, `updated_at` | `UNIQUE(env, namespace, name)`；`KEY(env, namespace, status)`；`KEY(expires_at)` | 密钥元数据；**不含明文 / 密文**；`version` 乐观锁；`active_version` 指向可解析版本；`dual_version=1` 时解析同时返回 active 与 grace 版本（验签类密钥） |
| `config_secret_version` | `id`, `secret_id`, `version`, `ciphertext`, `nonce`, `wrapped_dek`, `kek_key_id`, `algorithm`, `value_hash`, `status`, `created_by`, `created_at`, `revoked_at`, `destroyed_at` | `UNIQUE(secret_id, version)`；`KEY(secret_id, status)` | 密钥密文；`algorithm=aes-256-gcm`；`value_hash` 为指纹（SHA-256 前 8 位）；`status=active/grace/revoked/destroyed` |
| `config_secret_grant` | `id`, `env`, `namespace`, `service_identity`, `secret_id`, `permission`, `expires_at`, `created_by`, `created_at`, `revoked_at` | `UNIQUE(env, namespace, service_identity, secret_id)`；`KEY(secret_id)` | 服务授权；`permission=resolve`；禁止通配符；默认拒绝 |
| `config_secret_review` | `id`, `secret_id`, `action`, `reviewer`, `decision`, `comment`, `created_at` | `KEY(secret_id)` | 密钥审批记录；`action=create/rotate/revoke/grant`；提交人 ≠ 审批人 |
| `config_spec`（P1） | `env`, `namespace`, `key`, `owner`, `value_type`, `default_json`, `reloadable`, `status` | `PRIMARY KEY(env, namespace, key)` | 代码声明的 key 清单；`reloadable=startup/hot` |

**复用表**：`audit_event`（`config.*` / `config.secret.*`）、`async_outbox`（`config.release.*` / `config.secret.*`）。**不新建**审计表、事件表、权限表。

**索引与查询**：

- 版本轮询：`SELECT active_release_id, version FROM config_release_pointer WHERE env=? AND namespace=?`（主键）。
- 快照拉取：`SELECT ... FROM config_release WHERE id=?`（主键）；签名与快照同查。
- 管理面列表：`WHERE env=? AND namespace=? AND (key LIKE ? OR description LIKE ?) ORDER BY key LIMIT ? OFFSET ?`；禁止 `SELECT *`。
- 发布冲突：`UPDATE config_release_pointer SET active_release_id=?, version=version+1, updated_at=? WHERE env=? AND namespace=? AND version=?`；影响行数 0 → `40900`。
- 密钥解析：`SELECT v.ciphertext, v.nonce, v.wrapped_dek, v.kek_key_id, v.algorithm FROM config_secret s JOIN config_secret_version v ON v.secret_id=s.id AND v.version=? WHERE s.env=? AND s.namespace=? AND s.name=? AND s.status='active'`；必须先授权校验，再解密。
- 密钥授权：`SELECT 1 FROM config_secret_grant WHERE env=? AND namespace=? AND service_identity=? AND secret_id=? AND revoked_at IS NULL AND (expires_at IS NULL OR expires_at > NOW(3))`。
- 密钥轮换：`UPDATE config_secret SET active_version=?, version=version+1 WHERE id=? AND version=?`；影响行数 0 → `40900`。
- **禁止**：列表查询选取 `ciphertext` / `wrapped_dek`；日志或审计写入密文字段。

### 6.3 发布状态机

| 当前状态 | 动作 | 目标状态 | 守卫 |
|----------|------|----------|------|
| `draft` | submit | `pending_review` | 非空 Release；校验通过；提交人有 `config:write` |
| `pending_review` | approve | `approved` | 审批人 ≠ 提交人；有 `config:approve`；生产必须 |
| `pending_review` | reject | `rejected` | 需理由；审计 |
| `approved` | publish | `active` | 有 `config:publish`；指针 CAS 成功；快照 hash 校验 |
| `approved` | cancel | `cancelled` | 仅提交人 / 管理员；审计 |
| `active` | 新 Release publish | `superseded` | 旧指针被新 Release 替换 |
| `active` | rollback | `rolled_back` | 目标 Release 存在；新 Release 指向目标快照 |
| 任意非 active | archive | `archived` | P1；保留记录 |

**禁止转移**：`active → draft`、`pending_review → active`（跳过审批）、`rolled_back → active`（只能新建 Release）。

#### 6.3.1 密钥状态机

```text
Secret:        draft ──► pending_review ──► active ──► revoked ──► destroyed
                           │                   │
                           └──► rejected       └──► rotating（新版本进入 grace）

SecretVersion: pending ──► active ──► grace ──► revoked ──► destroyed
                              │          │
                              └──────────┴──► 仅保留密文，不再可解析（revoked）
```

| 当前状态 | 动作 | 目标状态 | 守卫 |
|----------|------|----------|------|
| `draft` | submit | `pending_review` | 有 `config:secret:write`；密钥名 / namespace / owner 完整 |
| `pending_review` | approve | `active` | 审批人 ≠ 提交人；有 `config:secret:approve`；生产强制 |
| `pending_review` | reject | `rejected` | 需理由；审计 |
| `active` | rotate | `active`（新版本 `active`，旧版本 `grace`） | 有 `config:secret:write` + 审批；KMS wrap 成功；旧版本保留 grace |
| `active` | revoke | `revoked` | 有 `config:secret:write` + 审批；租约 ≤ TTL 失效；审计 |
| `revoked` | destroy | `destroyed` | P1；密文物理清除；不可逆；双人确认 |
| 任意 | grant / revoke grant | 不变 | 独立授权表；审计；禁止通配符 |

**禁止转移**：`revoked → active`（只能新建密钥或新版本）、`pending_review → active`（跳过审批）、`destroyed → *`。

### 6.4 读路径时序

```text
启动（初始化阶段，不依赖外部配置）
  ├─ 读取代码默认值与 key spec（配置中心地址 / 环境 / 服务身份 / CA / 超时 / DB / Redis 连接参数）
  ├─ 首次启动（空库）：按 key spec 默认值播种基线 Release；按 secret_rule 生成密钥并加密入库
  ├─ 非首次：校验初始化状态；非法 → 启动失败（fail-fast）
  └─ 初始化日志 / OTel / DB / Redis（数据库 / Redis 口令由基础设施注入，不属于业务配置）

启动（配置阶段）
  ├─ 读取本地签名快照（release_id + hash + Ed25519 验签）
  ├─ 快照有效 → 原子装载；快照缺失 / 过期 / 验签失败 → 带 3s 超时拉取 pointer + snapshot
  ├─ 拉取成功 → 验签 → 原子写快照（临时文件 + fsync + rename）→ 装载
  ├─ 仍无 Release → 使用首次初始化生成的基线 Release（或代码默认值）
  ├─ required 键缺失且无法拉取 → 启动失败（fail-fast）
  └─ 否则使用快照 / 代码默认值启动，标记 degraded

启动（密钥阶段，M2）
  ├─ 通过 mTLS 调 config-api 解析 required 业务密钥
  ├─ 成功 → 写入内存租约缓存（不落盘）；失败 → required 密钥 fail-fast
  └─ 非 required 密钥 → 延迟解析；调用方按降级路径处理

运行
  ├─ 每 5s（±20% 抖动）查询 pointer.version
  ├─ 版本变化 → 拉取 snapshot（ETag / hash）→ 验签 → 原子替换 → 原子写本地快照
  ├─ 通知 Watch 回调（非阻塞、带缓冲）
  ├─ 密钥租约到期前 80% 异步刷新；吊销 / 轮换按 TTL 收敛
  └─ 更新指标：version / snapshot_age / fetch_result / secret_lease_active

读取
  ├─ 配置：atomic load → 类型化解码 → 命中返回；未命中 → 默认值 + 打点
  └─ 密钥：内存租约命中 → 返回；未命中 → config-api resolve → 校验 → 返回
```

**冷启动最坏路径**：1 次 pointer 查询 + 1 次 snapshot 查询，均为 PK / 唯一索引，P99 < 50ms；无本地快照时不得在请求路径同步拉取（启动期完成）。**签名快照不能替代事实源**：有中心时优先拉取最新快照；只有中心不可用才使用本地快照，并在恢复后立即校正。

### 6.5 写路径时序

```text
1. 创建 / 更新草稿（Item + ItemVersion；乐观锁 version）
2. 创建 Release（选择 item 版本；服务端校验；构建快照 JSON + hash）
3. 提交审批（status=pending_review；审计 config.release.submitted）
4. 审批（status=approved / rejected；审计 config.release.approved / rejected）
5. 发布（单事务）：
   a. SELECT pointer FOR UPDATE
   b. 校验 Release 状态、快照 hash、目标 namespace
   c. UPDATE config_release SET status='active', published_at=...
   d. UPDATE pointer CAS（version+1；影响行数 0 → 40900）
   e. INSERT async_outbox（config.release.published）
   f. 审计 config.release.published（与业务同事务 / 失败关闭）
   g. COMMIT
6. 提交后：Redis 缓存更新 / 失效广播（best-effort）；失败仅告警
7. 回滚：读取历史 Release 快照 → 创建新 Release（based_on_release_id）→ 走 5
```

**注意**：快照 JSON 在事务外构建；事务内只写元数据、指针、Outbox、审计。审计写入失败时发布失败（fail-closed），避免「配置生效但无审计」。

**密钥写路径（M2）**：

```text
1. 创建 / 轮换申请（管理员，一次性输入明文；浏览器 / API 请求体不落日志）
2. 服务端校验：名称、namespace、owner、长度、类型、授权范围
3. 生成 DEK（32 bytes, crypto/rand）→ AES-256-GCM 加密明文（AAD=env:namespace:name:version）
4. 调 KMS / Vault：wrap DEK（KEK 不落配置库；记录 key_id）
5. 明文清零（best-effort）→ 只保留 ciphertext / nonce / wrapped_dek
6. 提交审批（status=pending_review；审计 config.secret.submitted）
7. 审批（status=active / rejected；审计 config.secret.approved / rejected）
8. 激活（单事务）：
   a. INSERT config_secret_version（status=active）
   b. UPDATE config_secret SET active_version=?, version=version+1（CAS）
   c. 旧版本 → grace（保留至 grace 到期）
   d. INSERT async_outbox（config.secret.rotated）
   e. 审计 config.secret.rotated（同事务 / 失败关闭）
   f. COMMIT
9. 提交后：config-api 缓存失效；租约按 TTL 收敛；失败仅告警
10. 吊销：UPDATE status=revoked + 审计 + Outbox；租约 ≤ TTL 失效
```

**密钥写路径禁止**：

- 在事务内调用 KMS（远程调用可能超时，事务持有锁）；
- 把明文写入临时表、审计、Outbox、日志、错误信息；
- 在没有审批的情况下直接激活生产密钥；
- 用同一 DEK 加密多个版本或多个密钥。

### 6.6 灰度匹配算法（P1 设计，M1 不实现）

> **M1 状态（v0.4）**：本节仅作为 P1 的设计留档。M1 只支持 `strategy=all`，发布即切换
> `env + namespace` 的生效指针，客户端不做目标匹配；服务端对非 `all` 策略直接返回 `40000`。
> 之所以不保留「能存不能生效」的中间态，是因为那会让灰度规则看起来配置成功、实际全量生效。
> P1 落地本节时必须同时补齐：客户端目标匹配、`explain` 端点、以及 AC-CC 中新增的灰度验收项。

| 策略 | 规则 | 优先级 |
|------|------|--------|
| `tenant_list` | 显式租户 ID 列表 | 最高 |
| `instance_list` | 实例 ID / Pod 名列表（P1） | 高 |
| `channel_list` | `admin` / `biz` / `c` / `worker` | 中 |
| `percentage` | 0～10000 万分比 | 低 |
| `all` | 全量 | 最低 |

算法：

```text
bucket = hash(release_id + ":" + salt + ":" + target_id) % 10000
命中 = bucket < percentage
target_id 优先级：instance_id > tenant_id > channel > "global"
同一 Release 内 target 稳定；不同 Release 使用 release_id 作为 salt， cohorts 独立
```

- 首个命中规则生效；无命中 → 当前 `active` Release。
- `explain` API 返回：目标属性、命中 Release、规则、bucket、最终快照版本。
- 禁止随机数、时间窗口、嵌套条件、表达式求值。

### 6.8 配置优先级与热更白名单

**优先级（配置，M1 起生效）**：

```text
配置中心（tenant > namespace > global）> 代码默认值（key spec / applyDefaults）
```

**首次启动**：空库时不依赖外部配置，按代码 key spec 的默认值播种基线 Release；声明了 `secret_rule` 的密钥按规则生成并加密入库；初始化幂等、不覆盖已有值，**不产出引导配置清单或导入清单**。

**实现（现行，对齐 ADR-0016）**：业务进程经 `configboot` / `configclient` 从 `config-api` HTTP 拉取命名空间配置，合并代码默认值后 `normalize → Validate`；本地 dir 缓存仅作降级。热更白名单见 [ADR-0015](./adr/0015-config-hot-reload-whitelist.md)（`spec.HotKeys`，12 键）。永久排除分类见 `CONFIG_STANDARDS` §3.1.1。历史「文件双读 / 签名快照启动」路径已移除，不得回退。

**三类键，边界必须显式声明**：

| 类别 | 范围 | 来源 | 变更方式 |
|------|------|------|----------|
| **启动期配置** | `addr` / `shutdown_timeout`；`db.host/port/name/user`（口令走基础设施注入）；`redis.addr/db`（口令走基础设施注入）；`storage.driver/bucket`；`auth.issuer/audience/mode`；`tracing.exporter/endpoint`；`async.driver/broker`；`iam.mode`；`http.*` 服务器级限制 | **配置中心**（首次启动由代码默认值播种） | 发布 + 重启 / 滚动发布；`reloadable=startup` |
| **热更配置** | 限流阈值、分页上限、文案、白名单、通知重试次数、任务开关参数等 | **配置中心** | 发布 + 5s 收敛；`reloadable=hot` |
| **业务密钥** | 第三方 API Key、SMTP / 短信、Webhook 签名、业务加密 / 签名密钥 | **配置中心密钥子域**（M2；M1 签名类密钥按 `secret_rule` 首次生成） | 创建 / 轮换 + 审批 + 租约；生成规则见 CC-F-56 |
| **基础设施口令** | 业务进程 DB / Redis 口令、K8s 凭据、云账号根密钥、人员凭据 | 基础设施 / 部署编排 | 不入配置中心；按基础设施流程轮换 |

**禁止进入配置中心的键**：

```text
config_center.*（自身地址 / 凭据）
kms.* / vault.*（KEK 访问凭据）
db.password / redis.password / storage.s3.secret_key（基础设施口令）
auth.jwt.private_key（业务签名密钥，走密钥子域；首次启动按 secret_rule 生成）
云账号 AK/SK、K8s kubeconfig、SSH 私钥、人员口令
```

**禁止热更的键**（可在配置中心，但 `reloadable=startup`）：

```text
addr / shutdown_timeout / http.* / db.host / db.port / db.name / db.user
redis.addr / redis.db / storage.driver / storage.local.root / storage.s3.bucket
auth.issuer / auth.audience / auth.mode / tracing.exporter / tracing.endpoint
async.driver / async.broker / async.outbox / async.consumer / iam.mode
```

**白名单声明**：每个 key 必须在代码中声明（M1 落代码常量，P1 落 `config_spec`）：

```text
key / value_type / default / validation / required / owner / reloadable(startup|hot) / expires_at
密钥字段额外声明：secret_rule（min_len / max_len / encoding / algorithm / prefix / auto_generate）
```

SDK 启动时加载声明并校验；未声明的 key 即使存在于中心也忽略并打点，防止「配置中心偷偷改变行为」。**启动期配置变更必须走发布 + 重启，不得伪装成热更。**

### 6.9 与 featureflag 的边界

| 维度 | featureflag（ADR-0009） | 配置中心 |
|------|-------------------------|----------|
| 数据类型 | 布尔 | 字符串 / 数字 / 布尔 / 时长 / JSON |
| 变更单元 | flag | Release 快照 |
| 评估 | 规则引擎 + 稳定分桶 | Release 选择 + 类型化读取 |
| 缓存 | 5s kill switch / 30s 规则 | 5s 版本轮询；`Get` 进程内 |
| 审计 | `featureflag.*` | `config.*` |
| 典型场景 | 功能开 / 关、kill switch | 限额、文案、白名单、重试次数 |
| 禁止 | 存结构化配置 | 新增布尔开关语义 |

**组合用法**：需要「开关 + 参数」时，用 featureflag 控制是否启用，用配置中心提供参数；两者独立审计、独立回滚。

### 6.10 全量迁移与删除 `configs`

**迁移原则**：先自动扫描、再双读、后切换、最后删除；任何一步失败都可回退到文件层。

```text
S0 自动扫描（M0）
  ├─ CI 扫描 configs/** 全部 yaml / env / example，与代码 key spec 自动比对覆盖率
  ├─ 标记「启动配置 / 热更配置 / 业务密钥 / 基础设施口令」
  └─ 覆盖率 100%；不产出人工盘点清单，不新增仓库文档

S1 初始化（M1）
  ├─ 空环境按 key spec 默认值播种基线 Release
  ├─ 业务密钥按 secret_rule 自动生成；无规则密钥人工录入
  ├─ 不做导入清单；初始化 dry-run + 审计
  └─ 第三方密钥类配置留到 M2 迁移

S2 双读（M1）
  ├─ config_center.dual_read=true：同进程同时读文件与中心
  ├─ 每个 key 比对值、类型、默认值；差异打点 config_dual_read_mismatch_total
  ├─ 差异 > 0 → 阻断切换；修复后重新观察
  └─ 至少 7 天零差异 + 覆盖滚动重启

S3 切换（M1）
  ├─ config_center.enabled=true 成为默认；文件仅作兜底
  ├─ 按 namespace / 服务灰度切换；观察 1 个发布周期
  └─ 关闭双读；保留文件只读一个版本周期

S4 删除（M1 删非密钥 / M2 删密钥类 / M3 收口）
  ├─ M1 删除非密钥运行时文件；M2 迁移并删除密钥类文件
  ├─ M3 确认 configs/** 无运行时文件（不保留引导配置清单 / 导入清单）
  ├─ 删除 Loader 文件与环境变量覆盖路径及测试夹具
  ├─ CI 已启用 check-no-static-config（2026-11-12 提前落地）：禁止新增 configs 文件，迁移期基线只减不增
  └─ 首次无文件发布 + 回滚演练通过
```

**回退策略**：M1 / M2 保留文件只读兜底；M3 删除后回退依赖镜像回滚（上一版本仍含文件）或签名快照。**删除前必须完成一次「无文件启动」演练**，否则不得进入 M3。

### 6.11 签名快照

| 项 | 设计 |
|----|------|
| 生成 | `admin-api` 在发布事务提交后生成快照 JSON，计算 `sha256`，用 Ed25519 私钥签名；私钥属平台密钥（不放业务配置层；M2 起可纳入密钥子域，P1 可迁 HSM） |
| 内容 | `release_id`、`env`、`namespace`、`generated_at`、`config`（仅非密钥键值）、`hash`、`signature`、`key_id` |
| 排除 | **不含任何密钥值、密文、DEK、KEK、PII** |
| 存储 | MySQL `config_release.snapshot_signature` + 客户端本地文件；P1 可归档到对象存储 |
| 校验 | 客户端内嵌公钥（`go:embed`）；启动 / 拉取时验签；失败拒绝装载并告警 `ConfigSnapshotCorrupt` |
| 轮换 | 签名密钥支持 `key_id` 多版本；旧公钥保留一个发布周期；私钥泄露时吊销并全量重签 |
| 边界 | 快照只作冷启动与灾备兜底；有中心时以中心为准；快照不替代审批 / 审计 |

### 6.12 密钥信封加密与解析

**密文格式**（`config_secret_version`）：

```text
algorithm = "aes-256-gcm"
nonce     = 12 bytes（随机）
ciphertext = AES-256-GCM(DEK, plaintext, AAD)
AAD       = env + ":" + namespace + ":" + name + ":" + version
wrapped_dek = KEK.wrap(DEK)   // Vault Transit / KMS Encrypt
kek_key_id  = KEK 版本标识     // 支持轮换；不返回业务
value_hash  = SHA-256(plaintext)[:8] // 指纹，仅用于比对，不可逆
```

**解析流程**：

```text
Service → mTLS/SPIFFE → config-api
  ├─ 校验服务身份 + grant（env/namespace/service_identity/secret）
  ├─ 查 config_secret（status=active）+ active_version
  ├─ 查 config_secret_version：active 必查；dual_version=1 时同时查 grace
  ├─ DEK 缓存命中？否 → KMS.unwrap(wrapped_dek, kek_key_id) → 缓存 DEK（按 key_id + version）
  ├─ AES-256-GCM 解密（AAD 必须匹配）→ 校验 value_hash
  ├─ 生成租约（默认 5m，上限 15m；高风险可 60s / no-cache）
  └─ 返回 {name, version, value, [previous_version, previous_value], lease_expires_at}；
     审计 config.secret.resolved（只记版本，不记值）
```

**KEK 轮换**：

1. 在 KMS / Vault 创建新 `key_id`；
2. `config-api` 同时持有新旧 KEK，按 `kek_key_id` 选择 unwrap；
3. 后台任务逐条 `unwrap(old) → wrap(new)`，更新 `wrapped_dek` 与 `kek_key_id`；
4. 全部完成后，旧 KEK 保留 ≥ 最大租约 + 备份恢复窗口，再下线；
5. 轮换失败不回退明文；失败条目告警并重试。

**安全边界**：

- `config-api` 不提供「列出全部明文」「导出密文」「返回 DEK」的端点；
- 业务进程不持久化密钥；core dump / panic 日志不得包含请求体；
- 仅 `admin-api`（创建 / 轮换时 wrap）与 `config-api`（解析时 unwrap、轮换时重包裹）持有 KMS 访问凭据；业务进程无权限；建议 KMS 权限按 wrap / unwrap 拆分并分别绑定 ServiceAccount；
- `config-api` 与 `admin-api` 使用不同 ServiceAccount / 网络策略 / 证书。

### 7.2 上线阻断风险（Top 5）

1. **密钥明文旁路**：必须证明列表 / 详情 / 导出 / 日志 / 指标 / 错误体 / 前端 / 快照均无明文，越权解析被拒绝并审计；否则不得上线 M2。
2. **根密钥 / KEK 失守**：必须完成 KMS 权限最小化、双人控制、轮换与恢复演练；KEK 永不入库。
3. **全量迁移错漏**：必须完成盘点清单、7 天双读零差异、无文件启动演练；否则不得进入 M3。
4. **错值发布 / 密钥轮换失败**：必须完成校验、审批、灰度、回滚四件套，以及轮换双版本演练。
5. **冷启动不可用**：必须验证「无快照 + DB / KMS 故障」下的 fail-fast / 默认值 / 租约策略，关键服务与非关键服务分级。
6. **越权变更**：必须通过安全评审，覆盖自审批、跨租户、密钥授权、break-glass。

### 7.3 风险接受与例外

- 残留风险已在 2026-11-12 的 M0 评审中确认；新增残留风险须由架构、安全、SRE 三方确认后方可进入 M1。
- 任何「先上线后补审计 / 后补回滚」的请求视为高风险例外，须架构 Owner + 安全 Owner 书面同意，并登记 `docs/incident/ACTION_ITEMS.md`。
- 例外到期未关闭自动升级为 P1 事故项。

### 8.6 上线与回滚策略

**上线顺序**：

```text
M1：迁移（migrate Job）→ admin-api（含管理面）→ 业务进程（含 SDK + 签名快照）
    → 单 namespace 双读 → 切换 → 扩大 → 全量 → 删除非密钥文件

M2：迁移 secret 表 → 部署 cmd/config-api（mTLS / KMS 凭据 / 多副本）
    → 导入密钥 + 授权 → 业务进程接入 secretclient（required 分级）
    → 轮换 / 吊销演练 → 删除密钥文件
```

**回滚顺序**：

1. 若配置值错误：回滚 Release（目标 ≤ 30s）；签名快照同步回退；
2. 若配置中心不可用：SDK 使用本地签名快照 / 默认值；非密钥配置无需回滚数据；
3. 若密钥解析异常：业务进程使用租约缓存；过期后按 `required` 分级；**禁止回退明文或本地 KEK**；
4. 若密钥泄露：立即吊销 + 轮换 + 租约强制失效 + 安全事件流程；
5. 若 schema / 代码缺陷：回滚 admin-api / config-api 镜像；迁移只做向前修复，不 `down`（除非确认无数据）；
6. 若权限 / 审计异常：关闭写端点，保留读路径，按安全事件流程处理。
7. 若 KMS / Vault 故障：`config-api` 使用 DEK 缓存；禁止降级到本地根密钥；恢复后自动重包裹。

**灰度**：dev → staging → prod 单 namespace → prod 全量；每步观察 stale、发布失败率、5xx、业务指标。

### 附录 B：API 与错误码

> **M0 冻结**：本附录错误码、响应示例与 §6.7 operation 为契约冻结项；M1 / M2 实现不得新增或修改错误码语义，变更须走契约评审。

- 统一信封：`{ "code": 0, "message": "ok", "data": {}, "trace_id": "..." }`。
- 分页：`page` / `page_size`（≤100）/ `total`。
- 错误码复用：`40000` 参数错误、`40300` 无权限、`40400` 不存在、`40900` 版本冲突 / 状态冲突、`42900` 限流、`50000` 内部错误、`50300` 依赖不可用（KMS / `config-api`）。
- 发布冲突（指针 CAS 失败、Release 已被他人发布）返回 `40900`，`message` 不泄露内部版本号。
- 敏感项详情返回 `value_masked` 与 `fingerprint`，不返回明文；普通配置不得存密钥，密钥走 `/admin/v1/configs/secrets/*`。
- 密钥解析失败：未授权 `40300`；不存在 / 已吊销 `40400`；版本冲突 / 已轮换 `40900`；KMS 不可用 `50300`；错误体不含明文 / 密文 / DEK / KEK。
- `resolve` 成功示例：

```json
{
```

### 附录 E：术语

| 术语 | 含义 |
|------|------|
| Item | 一个配置 key 的草稿与版本集合 |
| Release | 一组 Item 版本的不可变快照，客户端按 Release 读取 |
| Pointer | `env + namespace` 当前生效 Release 的单行指针，CAS 切换 |
| Snapshot | Release 的 JSON 快照，含 key → value 与 hash |
| 签名快照（Signed Snapshot） | 对快照计算 hash 并用 Ed25519 签名，客户端内嵌公钥验签；用于冷启动与灾备兜底，不含密钥明文 |
| Stale | 客户端本地快照相对中心最新版本的滞后时间 |
| Explain | 解释某目标为何命中某 Release / 规则 / 桶 |
| break-glass | 紧急绕过审批的发布通道，强制事后补审 |
| 热更白名单 | 允许从配置中心读取并热更新的 key 集合 |
| 首次启动初始化（First-start Initialization） | 空库时按代码 key spec 默认值播种基线 Release，并按 `secret_rule` 生成密钥；不维护独立引导清单 |
| 业务密钥（Business Secret） | 第三方 API Key、SMTP / 短信、Webhook 签名、业务加密 / 签名密钥；不含根密钥与基础设施口令 |
| 密钥生成规则（secret_rule） | 密钥字段声明的长度、编码、算法、前缀与是否允许自动生成；首次启动仅对声明规则的字段用 `crypto/rand` 生成 |
| DEK | Data Encryption Key，每个密钥版本独立，用于 AES-256-GCM 加密明文 |
| KEK | Key Encryption Key，外部 KMS / Vault / HSM 持有，只用于 wrap / unwrap DEK |
| 信封加密（Envelope Encryption） | 用 DEK 加密数据、用 KEK 加密 DEK；密文与根密钥分离 |
| 租约（Lease） | `config-api` 返回密钥时附带的有效期；客户端内存缓存，到期前刷新 |
| Grant | 服务身份对某个密钥的解析授权；默认拒绝，禁止通配符 |
| SPIFFE / mTLS | 服务身份标准与双向 TLS；用于 `config-api` 认证调用方 |
| RPO / RTO | 恢复点目标 / 恢复时间目标 |
