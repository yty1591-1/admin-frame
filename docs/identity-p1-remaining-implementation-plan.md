## 1. P1-1 Argon2 移出数据库事务

### 1.1 现状与目标

**现状**

- `AuthService.Login` → `runTx(loginInTx)`，`PasswordService.VerifyContext` 在事务内执行 Argon2（约 19 MiB、t=2）。
- 事务连接在哈希期间被占用，高并发时 DB 连接池等待放大。

**目标**

- Argon2 校验在事务外完成；事务内只做「状态复核 + 写入」。
- 失败路径仍在事务内落库（登录尝试、审计、锁定）。
- 并发改密/禁用/锁定不得产生错误会话。

### 1.2 方案要点

```text
Phase A（无事务）
  限流 → 加载账号 → Authorize → 加载密码凭据 → Argon2 校验
  产出 loginProbe{accountVersion, credentialHash, verifyResult, failureReason, needsRehash}

Phase B（事务）
  重新加载账号与凭据
  比对 credential.hash / account.version / token_version / status
  不一致 → 401（提示重新登录），不创建会话
  一致 → 可选重哈希、激活 pending、MFA 闸门、RecordSuccess、createSession、审计
```

失败路径：

- Phase A 的失败（账号不存在/锁定/停用/无凭据/密码错误）进入事务 B，重新加载账号并写 attempt/audit；不重复 Argon2。
- 429/503 仍在事务外直接返回，不产生写入。

新增配置：

- 无运行时开关；回滚方式为回退应用版本（本次改造无 schema 变更）。
- 灰度策略：先在 staging 验证两阶段登录，再按发布窗口滚动升级；如需回退，直接回退上一镜像。

## 2. P1-2 降低 Redis 往返与回源风暴

### 2.1 现状与目标

**现状**

- 每个已认证请求：账号快照 + 会话快照 + jti 黑名单，2–3 次 Redis 读。
- 单进程 singleflight；多副本各自回源 DB。

**目标**

- 认证请求 Redis 往返 P95 ≤ 1 次（批量读或本地短缓存命中）。
- 撤销可见延迟仍 ≤ 1s（本地缓存 TTL）且不超过既有 ≤60s 承诺。
- Redis 故障时 DB 回源 QPS 可控，不放大为雪崩。

### 2.2 方案要点

1. **本地短缓存（L1）**：账号/会话快照 TTL 1s，容量上限 + LRU；本进程写操作后主动失效。
2. **批量读（可选增强）**：新增 `BatchRevocationStore` 接口，使用 MGET 一次读取账号/会话/jti 三个键；不支持时回退现有接口。
3. **singleflight 保留**：L1 miss 后仍合并同副本回源；跨副本通过 Redis TTL 收敛。
4. **指标**：`identity_revocation_l1_hit_total`、`identity_revocation_redis_calls_total`、`identity_revocation_db_refetch_total`。

### 2.3 任务拆解

| ID | 任务 | 责任 | 工时 | 依赖 | 交付物 |
|---|---|---:|---|---|---|
| T2-1 | L1 缓存设计与容量/TTL 评审 | TL+BE | 1 | P1-1 | 设计说明 |
| T2-2 | 实现 L1（LRU、TTL、并发安全、失效） | BE | 2 | T2-1 | 代码 + 单测 |
| T2-3 | Redis 批量读接口与 fallback | BE | 2 | T2-2 | 接口 + Redis/内存实现 |
| T2-4 | 写路径失效：logout/改密/停用/撤销 | BE | 1 | T2-2 | 代码 + 单测 |
| T2-5 | 指标与 dashboard | BE+SRE | 1 | T2-2 | 指标 |
| T2-6 | 故障注入与性能测试 | QA+SRE | 2 | T2-3 | 报告 |
| T2-7 | 缓存一致性回归（同副本/跨副本） | QA | 1 | T2-4 | 用例 |

### 2.4 验收标准

| 类别 | 标准 | 验证方式 |
|---|---|---|
| 功能 | 账号禁用/改密/登出/会话撤销在 1s 内本副本生效，跨副本 ≤ Redis 传播时间 | 双副本集成测试 |
| 性能 | 认证请求 Redis 往返 P95 ≤ 1；活跃账号 L1 命中率 ≥ 80% | 指标 + 压测 |
| 回源 | Redis 故障时 DB 回源 QPS ≤ 基线 1.5 倍；熔断生效 | Redis 停机 5 分钟故障注入 |
| 边界 | 缓存淘汰、键不存在、内容损坏、时钟回拨、TTL 边界 | 单测 + 注入 |
| 安全 | jti 黑名单不得本地缓存「未撤销」结果 | 代码审查 + 用例 |
| 回归 | 全量 `go test ./...`；refresh/replay/lockout 不变 | CI |
| 回滚 | 配置关闭 L1/批量读即回退旧路径 | staging 演练 |

### 2.5 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| L1 陈旧导致撤销延迟 | 安全 | TTL 1s；写后主动失效；jti 不缓存 |
| 批量读改变语义 | 404/fail_closed 误判 | 接口契约测试；fallback 旧路径 |
| 内存增长 | OOM | 容量上限 + LRU + 指标告警 |
| 多副本不一致 | 用户困惑 | 明确 ≤1s 本副本、≤60s 全局承诺 |

## 3. P1-4 会话归档/分区

### 3.1 现状与目标

**现状**

- 每次刷新插入新的 `identity_session`；保留期 30 天，清理删除旧行。
- 在线表会随刷新频率增长，清理虽有循环但只能删除，无归档。

**目标**

- 在线表行数稳定在「活跃设备 + 保留期内令牌代」规模。
- 历史会话可查询（归档表），不阻塞在线查询。
- 归档任务可追平日新增，且失败可恢复。

### 3.2 方案要点（推荐归档表，不做分区）

- 新增 `identity_session_archive`、`identity_session_family_archive`，结构与在线表一致，额外 `archived_at`。
- 清理任务在**同一事务**内「插入归档 + 删除在线」，按批处理。
- 归档保留期独立配置（默认 365 天）；到期后按批删除归档。
- 不改变现有 API；如需查询历史，新增内部仓储方法（不暴露 HTTP）。

## 4. P1-6 PII 加密 + 索引（分 3 个 release）

### 4.1 现状与目标

**现状**

- A/B 端 `identity_account.subject` 明文；OAuth `provider_subject` 明文；管理列表原样回显。
- 唯一键依赖明文 subject。

**目标**

- 库内不保存可读 PII；登录仍可按确定性索引查找。
- 支持密钥轮换双读；支持灰度回滚。
- 存量数据 100% 回填，业务无感。

### 4.2 方案要点（5 阶段）

| 阶段 | 内容 | 是否可回滚 |
|---|---|---|
| S1 | 新增 `subject_index`、`subject_ciphertext` 列（可空）与非唯一索引；双写 | 是（保留明文） |
| S2 | 读路径：先 index 查找，未命中回退明文；写路径双写 | 是 |
| S3 | 回填任务：按批加密存量 subject，写 index/ciphertext | 是（可重跑） |
| S4 | 唯一键切换到 `(channel,merchant_id,subject_index)`；校验无重复 | 是（切回旧键） |
| S5 | 停止写明文；灰度稳定后删除 `subject` 明文列与旧唯一键 | 需提前备份 |

密钥：

- `subject_index` = `HMAC-SHA256(key, "account-subject|channel|merchant|normalizedSubject")`，复用 `crypto.Hasher` 的 key id 双读。
- `subject_ciphertext` = AES-256-GCM，AAD=`identity:account:<accountID>`；复用 `crypto.KeyRing` 轮换。
- OAuth `provider_subject` 同样增加 index/ciphertext，唯一键切换到 index。

| 回填中断 | 部分数据不可查 | 断点续跑 + 校验和 + 双读回退明文 |
| 唯一键冲突 | 迁移失败 | 预检脚本；人工合并；分批切换 |
| 性能退化 | 登录变慢 | index 覆盖查询；压测门禁 |
| 误删明文 | 不可逆 | S5 前全量备份 + 延迟一个 release 删除 |

## 5. P1-14 权限粒度拆分

### 5.1 现状与目标

**现状**

- 仅 `identity:account:read` / `identity:account:write`。
- 读、会话撤销、凭据重置、删除共用 write，不符合职责分离。

**目标**

- 四类动作权限独立：读、生命周期写、凭据重置、删除、会话撤销。
- 旧角色迁移后行为不变；无权限时 403 失败关闭。

### 5.2 权限矩阵

| 权限码 | 覆盖路由 |
|---|---|
| `identity:account:read` | GET accounts、GET account、GET account sessions |
| `identity:account:write` | disable/enable/lock/unlock/restore |
| `identity:account:credential` | password/reset、mfa/reset |
| `identity:account:delete` | DELETE account |
| `identity:account:session` | DELETE session、sessions/revoke-all |

### 5.3 任务拆解

| ID | 任务 | 责任 | 工时 | 依赖 | 交付物 |
|---|---|---:|---|---|---|
| T14-1 | 权限模型与路由矩阵评审 | TL+SEC | 1 | 无 | 矩阵文档 |
| T14-2 | 新增 PermissionCode 与 catalog 条目 | BE | 0.5 | T14-1 | 代码 |
| T14-3 | 种子迁移：新增权限 + 授权给原 write 角色 | DBA+BE | 1.5 | T14-2 | up/down SQL |
| T14-4 | 路由中间件切换到新权限 | BE | 1 | T14-3 | 代码 |
| T14-5 | 403/授权矩阵测试 | QA | 2 | T14-4 | 测试报告 |
| T14-6 | 文档与 OpenAPI 权限说明 | BE | 0.5 | T14-4 | 文档 |
| T14-7 | 灰度双跑（旧/新权限比对） | SRE | 1 | T14-4 | 比对报告 |

### 5.4 验收标准

| 类别 | 标准 | 验证方式 |
|---|---|---|
| 功能 | 各权限码仅能访问其矩阵内路由；缺失返回 40300 | 参数化权限矩阵测试 |
| 兼容 | 原持有 write 的角色迁移后仍可执行原全部操作 | 迁移前后行为对比 |
| 最小权限 | 仅 credential 权限不能删除账号/撤销会话 | 负向用例 |
| 安全 | 无权限中间件时失败关闭（403） | 路由单测 |
| 边界 | 多权限组合、wildcard、跨端访问 | 用例 |
| 回归 | IAM catalog/种子测试全绿；`go test ./...` | CI |
| 回滚 | 回滚迁移后旧权限仍可用 | staging 演练 |

### 5.5 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 迁移漏授权导致管理员失权 | 运维中断 | T14-3 先授权后切路由；灰度双跑 |
| 权限码扩散 | 管理复杂 | 固定 5 个码，不新增动作级细粒度 |
| 文档不同步 | 误用 | OpenAPI + PERMISSIONS 同步更新 |
