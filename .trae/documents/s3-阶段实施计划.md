# S3 阶段实施计划（落地文档 frontend-s3-plan.md）

## Context

用户已批准 `docs/frontend-s3-plan.md`，要求在现有 `frontend/` monorepo 中落地 S3 基础设施：统一错误码文案与展示位置、可定位的前端日志与 trace_id、首屏后动态加载的 OTel 上报、以及可门禁的 zh-CN 文案字典。基线为 `main@90da8b9`（S1/S2 已落地）。本计划只按该方案执行，不扩展范围、不提交 git。

已确认决策：i18n 自研零依赖；OTel 依赖只允许出现在 `packages/observability`；release 取 `monitoring.release ?? __APP_VERSION__`；chunk 刷新去重使用 `sessionStorage` 单文件例外；文案门禁用 CI 脚本扫描 CJK；`traceparent` 非目标；B 端只接 i18n 与错误映射，不接 Toast/OTel。

## 批次与顺序

### S3-1 i18n 基座与错误码映射

新增 `frontend/packages/i18n`（`@admin-frame/i18n`）：

- `package.json`：零 dependencies，`react` 仅 peer；`tsconfig.json` 继承基线；`src/index.ts` 公共出口。
- `src/messages/zh-CN.ts`：扁平 `zhCN = {...} as const`，导出 `MessageKey = keyof typeof zhCN`；按 `common/nav/auth/error/iam/permission` 分组前缀，覆盖现有全部页面、ui、entities 中文文案（含开发者异常 `error.dev.*`，避免门禁例外）。
- `src/translate.ts`：`createTranslator()`，`{name}` 插值；缺失 key 返回 key 并去重记录 `missingKeys`（不 console）。
- `src/i18n-provider.tsx`：`I18nProvider` 与 `useI18n()`；无 Provider 时回退默认 zh-CN 翻译器，保证 ui 既有测试零改造。
- `src/error-presentation.ts`：`describeError(unknown)` 结构化读取 `code/kind/traceId`（最多 3 层 cause，try/catch），不 import api-client；优先级 code → kind → unknown；映射 8 个业务码 + network/timeout/unknown，40900 → `approval` 且 `retryable=false`。
- 单测：`translate.test.ts`、`i18n-provider.test.tsx`、`error-presentation.test.ts`（11 场景表驱动 + 40900 不重试 + cause 链 traceId + 非法输入不抛错）。

接入改动：
- `frontend/tsconfig.base.json` paths 增加 i18n；两端 `package.json` 增加 workspace 依赖。
- `apps/admin-web/src/app/App.tsx`：`ThemeProvider` 内、`ToastProvider` 外插入 `I18nProvider`；`apps/biz-web/src/app/App.tsx` 同理（不接 Toast）。
- `RoleListPanel.tsx`、`PermissionCatalogPanel.tsx` 的列表/删除错误改用 `describeError` + `t()`，保留 trace_id 复制；`LoginPage.tsx` 的 `toLoginError` 改为返回 `messageKey`，40100 用 `auth.invalidCredentials`，移除后端 `message` 直出。

### S3-2 logger、trace_id 与错误边界

新增 `frontend/packages/observability`（`@admin-frame/observability`，无 runtime 依赖）：

- `logger.ts`：级别过滤、字段白名单、敏感键脱敏、字符串截断 200、非原始类型 `[object]`、环形缓冲 50、可注入 sink（默认只写缓冲）、sink 异常吞掉；模块加载即有默认配置。
- `trace.ts`：`getTraceId` / `ensureTraceId`，cause 链读取，非法格式拒绝，缺失时 `crypto.randomUUID()` 并标记 `clientGenerated`。
- `report.ts`：`reportError` + `setReportTransport`，transport 未就绪时缓冲最近 20 条，注入后补发。
- `chunk-reload.ts`：识别 `ChunkLoadError` / dynamic import 失败等；`admin_frame_chunk_reload_guard` 只允许刷新一次；storage 异常返回 false。
- 单测覆盖上述四个模块的行为约定。

装配改动：
- `apps/admin-web/src/app/AppErrorBoundary.tsx` 与 biz 同文件：删除 `console.error`，改 `logger.error` + `reportError`。
- 新增 `apps/admin-web/src/app/observability/ObservabilityProvider.tsx`（只做装配，不包 UI）与 `apps/admin-web/src/app/RouteErrorBoundary.tsx`（包裹 `Outlet`，chunk 错误先尝试一次刷新）。
- `App.tsx` 增加 `QueryCache.onError`（`event:'query.error'`，不弹 toast）并装配 ObservabilityProvider。
- `AppLayout.tsx` 用 RouteErrorBoundary 包裹 Outlet。
- `packages/config/src/eslint-base.mjs`：移除 apps 装配层的 `no-console` 例外；新增 OTel 导入限制与 chunk-reload 单文件 `sessionStorage` 例外（附理由）。
- `dependency-cruiser.cjs`：新增 `i18n-is-leaf`、`observability-is-leaf`、`otel-only-in-observability`，并收紧既有包规则。

### S3-3 OTel Web 接入（仅 A 端）

- `observability/src/privacy.ts`：上报属性白名单 `service.name/version`、`deployment.environment`、`page.route`、`error.code/kind/source`、`trace.id`、`client.trace.id`；路由去 query/hash；敏感键丢弃。
- `observability/src/otel.ts`：`initObservability` 幂等；`endpoint` 为空或 `sampleRate<=0` 时直接禁用（零 import、零请求）；首屏后 idle 动态 import；`TraceIdRatioBasedSampler`；span 名 `frontend.error`；失败只 `logger.warn`。
- `package.json` 增加 5 个 OTel 依赖并核对 license（Apache-2.0 已允许）：`@opentelemetry/api@1.9.0`、`sdk-trace-web@2.12.0`、`exporter-trace-otlp-http@0.223.0`、`resources@2.12.0`、`semantic-conventions@1.43.0`（避免 3.0/0.300 与 2.x 不兼容）。
- `packages/shared/src/runtime-config.ts` 的 `monitoring` 增加可选 `release`（缺省 null），同步 zod、返回结构与运行期配置样例；新增单测。
- `ObservabilityProvider` 计算 release 并调用 `initObservability`；B 端不接。
- 体积：OTel 必须为动态 chunk；若单 chunk >120KB，在 admin vite 配置用 `manualChunks` 拆 `otel-sdk`/`otel-exporter`，禁止放宽预算。

### S3-4 文案迁移、离开提示与文案门禁

- 迁移 `packages/ui` 内置文案（error-state/table-shell/empty-state/dialog/danger-action/page-loading/page-skeleton/app-shell/toast）到 `useI18n()`，默认值保持原文；`packages/ui/package.json` 增加 i18n 依赖。
- 迁移 apps：pages、app（routes 的 `title` → `titleKey`、AppLayout、FatalConfigError、main.tsx）、features、entities（`label` → `labelKey: MessageKey`，`tone` 不变）。菜单在 AppLayout 渲染时 `t(labelKey)`，不改变 `AppShellMenuEntry` 形状。
- 新增 `apps/admin-web/src/shared/use-unsaved-changes-guard.ts`：`useBlocker` + `beforeunload`，返回 `{ blocked, proceed, reset }`；只提供能力与注释，本轮不接页面。
- 新增 `frontend/scripts/check-i18n.mjs`：扫描 `apps/*/src` 与 `packages/ui/src`，汉字正则，行级剥离注释，`// i18n-ignore -- 理由` 豁免（无理由视为违规），失败列出 `文件:行号` 并退出 1。
- `frontend/package.json` 增加 `lint:i18n` 并插入 `ci` 串联；`scripts/ci/check-frontend.sh` 在 eslint 后执行。

## 风险与规避

- OTel peer 冲突：钉扎上述版本，`pnpm install` 须零 peer 警告；失败则调整版本但仍保持 2.x 一致。
- 字典进入首屏：先记录 `pnpm size` 基线；超标时按路由拆子字典。
- ui 测试破坏：`useI18n()` 无 Provider 回退且默认文案逐字保持原文。
- chunk 刷新循环：一次性标记 + 二次仅提示；成功渲染后重置。
- `exactOptionalPropertyTypes`：可选字段统一 `?: T | undefined`，构造对象时省略而非赋 undefined。

## 已采纳的默认决策

1. 开发者异常文案纳入 `error.dev.*` 字典，门禁零例外。
2. chunk 二次失败复用 `ErrorState`（含 trace_id），不新增独立错误页。
3. OTel 使用上表钉扎版本组合。
